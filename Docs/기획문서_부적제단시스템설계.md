# 부적(Talisman) & 제단(Altar) 시스템 설계

> [기획문서_상점시스템설계.md](./기획문서_상점시스템설계.md) 7장에서 "재료 소모 → 무기 레벨업"으로 정의했던 **강화(Upgrade)** 개념을 재정의한다. 이제 강화는 플레이어가 **부적(Talisman)을 소지(장착)** 함으로써 버프·능력치 상승을 얻는 방식으로 동작한다.
> 여기에 더해, 벙커/기지에 놓인 **제단(Altar)** 오브젝트에 여분의 부적을 봉헌하면 행운·거래비용감소 등 **영구 시설 버프**를 얻는 시스템을 추가한다.
> NPC/오브젝트 상호작용 트리거 자체, 인벤토리 시스템 본체, 루팅(드랍) 시스템은 **별도 문서에서 다룬다** — 본 문서는 부적/제단 UI의 구조와 기존 시스템(상점·대화)과의 연결 고리만 다룬다.
> 작성일: 2026-09-17

---

## 1. 설계 원칙

1. **기존 "무기 레벨업형 강화"를 대체한다.** [상점시스템설계](./기획문서_상점시스템설계.md) 7장의 재료 소모 강화는 본 문서로 폐기·대체되며, 상점의 "강화" 탭은 **부적 장착(Loadout) 화면**을 여는 진입점으로 역할이 바뀐다(2장·6장 참고). 이유: 재료 소모형 선형 강화보다, 아이템(부적)을 찾고 골라 장착하는 방식이 루팅 기반 전투 루프와 더 잘 맞물리고 "이번엔 어떤 부적을 낄까"라는 반복 선택의 재미를 준다.
2. **부적은 무기 전용이 아니라 캐릭터 전체에 적용되는 장신구**다. 소지(장착)만 하면 효과가 발동하며, 특정 무기에 종속되지 않는다.
3. **제단은 상점과 다른 진입 경로를 쓴다.** 상점/부적 장착은 NPC 대화의 `Event` 노드로 열리지만, 제단은 인격을 가진 대화 상대가 없는 **오브젝트**이므로 대화 그래프를 거치지 않고 상호작용 성공 시 곧장 제단 UI를 연다(4장). NPC/오브젝트 상호작용 트리거 자체의 판정 로직은 후속 문서에서 정의하되, "상호작용 성공 → 지정된 UI를 연다"는 연결 방식 자체는 부적 장착(NPC 경유)이든 제단(오브젝트 직결)이든 동일한 패턴을 따른다.
4. **입력은 새 Action Map 없이 기존 `UI` 맵을 재사용**한다([UI조작설계](./기획문서_UI조작설계.md)).

## 2. 부적(Talisman) 아이템

### 2.1 데이터 구조 (개념)

```
TalismanData
├─ id
├─ name / icon / description
├─ rarity: enum { Common, Rare, Epic, Legendary }
├─ effectType: enum { AttackPower, MoveSpeed, CritChance, DamageReduction, ReloadSpeed, Luck, ... }
└─ effectValue: float   // 등급이 높을수록 큰 값 (2.2절)
```

- 부적 1개는 **효과 1종**만 가진다(다중 옵션 없음) — 저작·밸런싱 비용을 낮추고, "이 부적은 무엇을 위한 것인지" 플레이어가 한눈에 파악하게 하기 위함(결정 사항).

### 2.2 등급별 효과치 예시

| 등급 | 효과 배율(기준) | 비고 |
|---|---|---|
| 일반(Common) | 100% | 예: 공격력 +3% |
| 희귀(Rare) | 180% | 예: 공격력 +5.4% |
| 영웅(Epic) | 300% | 예: 공격력 +9% |
| 전설(Legendary) | 500% + 고유 연출 | 예: 공격력 +15%, 장착 시 특수 이펙트 |

### 2.3 획득 경로

- **전투 드랍**(적 처치 시 확률 획득) — 후속 루팅 시스템 문서에서 확률 테이블 정의.
- **상점 구매** — 새 탭을 만들지 않고 [상점시스템설계](./기획문서_상점시스템설계.md) 4장의 **구매(Buy) 탭**을 그대로 사용한다. `ShopItemEntry`가 이미 임의의 아이템을 판매하도록 설계돼 있으므로, 부적도 일반 아이템처럼 `buyCatalog`에 넣으면 된다 — 상점 구조 변경 불필요.
- **퀘스트 보상** — [퀘스트UI설계](./기획문서_퀘스트UI설계.md)의 `rewards` 목록에 부적을 아이템처럼 넣으면 된다(별도 처리 불필요).

## 3. 부적 장착(Loadout) 화면 — 상점 "강화" 탭의 새 정의

### 3.1 레이아웃

```
┌─────────────────────────────────────────────┐
│ [NPC 초상화] NPC 이름                          │
│ ───────────────────────────────────────────  │
│  장착 슬롯                                     │
│   [슬롯1: 공격력+5%]  [슬롯2: 빈 슬롯]  [슬롯3: 잠김] │
│ ───────────────────────────────────────────  │
│  보유 부적 목록                                 │
│   [아이콘] 이동속도+4%(일반)                     │
│   [아이콘] 크리티컬+6%(희귀)                     │
│   [아이콘] 행운+3(일반)                          │
│ ───────────────────────────────────────────  │
│              [ 장착(Submit) ]  [ 해제/뒤로 ]     │
└─────────────────────────────────────────────┘
```

- `Navigate`로 슬롯/목록 이동, `Submit`으로 "슬롯 선택 → 장착할 부적 선택 → 확정" 2단계 흐름.
- 이미 장착된 부적이 있는 슬롯을 다시 선택하면 [교체] 또는 [해제] 옵션이 뜬다.
- **결정 사항**: 부적 장착/해제/교체는 골드나 재료를 소모하지 않는다(자유 교체) — "어떤 부적을 낄지 실험"하는 행위 자체가 재미 요소이므로 비용을 매기지 않는다. 대신 잉여 부적의 처분(판매/봉헌)에는 비용 개념이 자연히 따라붙는다(5장 제단).
- **슬롯 수**: 기본 3개, 4번째 슬롯부터는 잠김(🔒) 상태로 표시되며 제단 레벨업으로 해금된다(4.3절) — 부적과 제단이 진행도로 연결되는 지점.

### 3.2 상점 데이터 반영

```
ShopData (기존 필드 갱신)
├─ capabilities: { canBuy, canSell, canExchange, canTalismanLoadout }  // canUpgrade → canTalismanLoadout으로 대체
└─ (upgradeRecipes 필드 제거 — 더 이상 사용하지 않음)
```

- [상점시스템설계](./기획문서_상점시스템설계.md) 3.1절의 `capabilities.canUpgrade`/`upgradeRecipes`는 본 문서로 대체되므로 제거하고, `canTalismanLoadout`으로 이름을 바꾼다. 대장장이 NPC는 여전히 "강화" 탭이라는 이름의 UI 버튼을 노출하되, 실제로 여는 화면은 3.1절의 장착 화면이다(플레이어 입장에서는 탭 이름만 같고 내용이 바뀐 것으로 느껴짐 — 자연스러운 전환).
- 대화 `Event` 타입도 함께 갱신: `OpenShop(shopId)` 진입 후 "강화" 탭을 누르면 내부적으로 3.1절 화면을 그린다(별도의 새 `Event` 타입을 추가할 필요 없음 — 상점 모달 내부 탭 전환이므로).

## 4. 제단(Altar) — 오브젝트 상호작용으로 직결

### 4.1 진입 경로

| 경로 | 트리거 | 결과 |
|---|---|---|
| 오브젝트 상호작용 | 벙커/기지의 제단 오브젝트를 `Interact`(F)로 상호작용 (판정 로직은 후속 문서) | 대화 그래프 없이 곧장 제단 UI를 모달로 오픈 |
| 제단 UI 닫힘(`Cancel`) | 봉헌을 마침 | 게임플레이로 즉시 복귀(대화로 돌아갈 지점이 없으므로 3장의 `nextNode` 개념 자체가 불필요) |

- 제단은 대사가 없는 순수 기능 오브젝트이므로 [대화시네마틱구조설계](./기획문서_대화시네마틱구조설계.md)의 시퀀스/노드 구조를 전혀 거치지 않는다 — 이 점이 상점·부적 장착(NPC 경유)과의 핵심 차이다.

### 4.2 레이아웃

```
┌─────────────────────────────────────────────┐
│  제단                     레벨 2 (다음까지 3/5)   │
│ ───────────────────────────────────────────  │
│  활성화된 축복                                  │
│   ・ 행운 +5 (전리품 등급 확률 증가)               │
│   ・ (2번째 슬롯 — 레벨 3에서 해금)                │
│ ───────────────────────────────────────────  │
│  봉헌할 부적 선택 (보유 부적 목록)                 │
│   [아이콘] 이동속도+4%(일반)                     │
│   [아이콘] 방어력+2%(일반)                       │
│ ───────────────────────────────────────────  │
│              [ 봉헌(Submit) ]  [ 취소(Cancel) ] │
└─────────────────────────────────────────────┘
```

- `Navigate`로 봉헌할 부적 선택, `Submit`으로 봉헌 확정.
- **결정 사항**: 봉헌은 부적을 영구 소모하는 되돌릴 수 없는 행동이므로, [퀘스트UI설계](./기획문서_퀘스트UI설계.md) 3.2절의 "포기하기"와 동일한 패턴으로 **재확인 팝업**을 한 번 더 띄운다(구매/판매/부적 장착과 달리 예외적으로 확인 단계를 둠 — 되돌릴 수 없는 손실이기 때문).
- 봉헌은 부적의 등급과 무관하게 **1회 봉헌 = 진행도 +1**로 단순화한다(등급별 가중치를 주면 "어떤 부적을 바쳐야 손해가 적은지" 계산하게 만들어 오히려 잉여 부적 처분이라는 목적을 흐릴 수 있음).

### 4.3 제단 레벨과 축복(Blessing)

| 제단 레벨 | 해금 내용 | 필요 봉헌 수(누적) |
|---|---|---|
| 1 | 축복 슬롯 1개 | 시작 레벨 |
| 2 | 축복 슬롯 2개, 부적 장착 4번째 슬롯 해금(3.1절과 연동) | 5회 |
| 3 | 축복 슬롯 3개 | 12회 |
| 4 | 축복 슬롯 4개, 부적 장착 5번째 슬롯 해금 | 25회 |
| 5(최대) | 모든 축복 동시 적용 + 특수 연출 | 45회 |

- 각 레벨업 시점에 플레이어가 **축복 목록 중 하나를 직접 선택**해 슬롯에 배정한다(자동 지급 아님 — 선택의 재미).
- 축복 목록 예시:

| 축복 | 효과 | 연동 지점 |
|---|---|---|
| 행운 증가 | 전리품 등급(레어도) 확률 상승 | 후속 루팅 시스템 |
| 거래비용감소 | 모든 상점의 구매가 할인 / 판매가 우대 (전역 배율) | [상점시스템설계](./기획문서_상점시스템설계.md)의 가격 계산식에 곱해지는 전역 배율로 적용 |
| 경험치 획득량 증가 | 처치/퀘스트 경험치 보너스 | 후속 성장 시스템 |
| 체력 재생 속도 증가 | 비전투 시 체력 회복 속도 상승 | 메인 기획서의 체력/실드 구조 |

- **결정 사항**: 축복은 슬롯당 1개씩 **동시에 여러 개 활성화**될 수 있다(레벨이 오를수록 슬롯이 늘어나므로 자연히 다다익선 구조). 슬롯에 배정한 축복은 이후 재배정 가능(재화 소모 없이 자유 변경, 3.1절의 부적 장착과 동일한 "자유 교체" 철학).


## 6. 입력 처리 요약

| 액션 | 부적 장착 화면 | 제단 화면 |
|---|---|---|
| `Navigate` | 슬롯/목록 이동 | 봉헌 대상/축복 목록 이동 |
| `Submit` | 슬롯 선택 → 부적 선택 → 장착 확정 | 부적 선택 → 봉헌 확정(재확인 팝업 후 최종 확정) |
| `Cancel` | 선택 취소 / 화면 닫기 | 선택 취소 / 화면 닫기 |

- 새로 추가되는 액션 없음 — [UI조작설계](./기획문서_UI조작설계.md)의 기존 액션만 사용.

## 7. 결정 사항 요약

- **강화 개념 재정의**: 재료 소모형 무기 레벨업 → **부적을 장착(소지)해 버프를 얻는 방식**으로 대체. 상점의 "강화" 탭은 이제 부적 장착 화면을 여는 진입점.
- 부적은 **효과 1종/개**, 등급(일반/희귀/영웅/전설)에 따라 효과치가 커짐.
- 부적 획득은 새 시스템을 만들지 않고 **기존 상점 구매 탭 / 퀘스트 보상 / 전투 드랍**을 그대로 활용.
- 부적 **장착/해제/교체는 무료**(자유 실험 장려), 슬롯은 기본 3개이며 제단 레벨업으로 확장.
- 제단은 **NPC 대화를 거치지 않고 오브젝트 상호작용으로 직결**되는 UI — 상점/부적 장착(NPC 경유)과 진입 경로가 명확히 다름.
- 제단 **봉헌은 부적을 영구 소모**하며, 되돌릴 수 없으므로 재확인 팝업 필수(구매/판매/장착과 달리 예외적으로 마찰 추가).
- 제단은 레벨업마다 **축복 슬롯이 늘고, 플레이어가 직접 축복 종류를 선택**해 배정. 행운/거래비용감소 등은 기존 루팅·상점 시스템의 계산식에 곱해지는 전역 배율로 연동.

## 8. 추가 권장 사항

- **부적 정렬/필터 UI**: 부적 개수가 많아지면 등급/효과 타입별 정렬·필터가 필요 — [UI조작설계](./기획문서_UI조작설계.md)의 `TabNext`/`TabPrev`를 정렬 기준 전환에 재사용하는 것을 권장.
- **봉헌 미리보기 강조**: 제단 화면에서 다음 레벨까지 남은 봉헌 수와 다음 해금 내용(예: "5번째 봉헌 시 축복 슬롯 2 해금")을 목록 상단에 항상 노출해 동기 부여.
- **중복 부적 처리**: 완전히 동일한 효과의 부적을 여러 개 보유했을 때 자동으로 "봉헌 후보"로 표시해주는 편의 기능을 권장(잉여 부적을 빠르게 골라 봉헌할 수 있게).
- **전설 등급 부적 연출**: 장착 시 캐릭터 주변에 은은한 파티클 등 시각적 차별화를 줘 희소성을 체감시킬 것을 권장.
- **디버그 연동**: [캐릭터조작설계](./기획문서_캐릭터조작설계.md) 8장의 개발자 콘솔(F1)에서 임의의 부적 즉시 지급 / 제단 레벨 즉시 조정 명령을 지원하면 밸런싱 QA가 수월하다.

## 9. 후속 설계 범위

- NPC/오브젝트 상호작용 트리거 시스템(제단을 포함한 모든 오브젝트의 감지·판정 로직) — 여러 문서에서 반복 언급된 공통 후속 항목.
- 인벤토리 시스템 본체 — 부적을 아이템으로 보유·조회하는 실제 데이터 계층.
- 루팅(드랍) 시스템 — 부적의 처치 드랍 확률 테이블, 등급 가중치.
- 성장(경험치/레벨) 시스템 — "경험치 획득량 증가" 축복이 실제로 연동될 대상.
- 축복 수치 밸런싱(행운이 전리품 등급 확률에 정확히 얼마나 영향을 주는지 등).
