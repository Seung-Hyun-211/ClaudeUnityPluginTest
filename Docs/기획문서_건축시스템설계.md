# 건축(맵빌딩) 시스템 설계

> 플레이어가 벽·바닥·계단·문·사다리를 그리드에 맞춰 배치해 구조물을 짓고, 이를 통해 적의 진입을 막아낼 수 있는 **건축 시스템**을 설계한다.
> 그리드 단위, 피스별 치수(벽 두께 0.5, 층고 3.0 등), 레이캐스트 기반 자석 스냅 프리뷰, 입력 체계, 내구도/자원 소모 규칙을 다룬다.
> NPC/오브젝트 상호작용 트리거 본체, 적 AI의 NavMesh 재계산 세부, 인벤토리 시스템 본체는 **별도 문서에서 다룬다**.
> 작성일: 2026-09-20

---

## 1. 설계 원칙

1. **모든 배치는 그리드에 종속된다.** 자유 배치(그리드 무시)는 허용하지 않는다 — 그래야 벽/바닥이 항상 빈틈없이 맞물리고, 방어 구조물로서 신뢰할 수 있는 형태가 나온다.
2. **벽·바닥·계단·사다리·문 5종으로 범위를 한정**한다(지붕/창문 등 확장 피스는 후속 문서).
3. **구조물은 파괴 가능**해야 한다 — 내구도(HP)를 부여해 적의 공격으로 부서질 수 있게 하여, "적을 막아낸다"는 목적에 실제 긴장감을 준다.
4. **건축은 자원을 소모**한다 — 인벤토리의 재료를 사용하며, 상점 구매 탭을 통해서도 재료를 조달할 수 있다(기존 상점 시스템 재사용, 새 탭 불필요).
5. **입력은 새 Action Map을 만들지 않는다.** `Player` 맵 안에 "건축 서브모드"를 두고, 기존 전투 액션(LMB/RMB/휠/숫자키)을 컨텍스트에 따라 재해석한다 — 이 시리즈 전체에서 반복해온 "같은 물리 입력을 상태에 따라 다르게 해석" 관용구를 그대로 따른다.

---

## 2. 그리드 & 좌표계

- **기준 유닛**: 가로/세로(X, Z) 1m 그리드. 모든 배치는 이 1m 격자에 스냅된다.
- **층 높이(수직 기준)**: 바닥 두께 0.5m + 내부 유효 높이 2.5m = **한 층당 3.0m**. 여러 층을 쌓을 때 다음 층 바닥은 정확히 현재 층 바닥 기준 +3.0m 지점에 스냅된다.

```
        ┌──────────────┐  ← 2층 바닥 하단 (1층 기준 +3.0m)
        │   2층 내부    │  2.5m
        │              │
        ├──────────────┤  ← 2층 바닥 슬래브 (두께 0.5m)
        ├──────────────┤  ← 1층 벽 상단 = 1층 천장 높이
        │   1층 내부    │  2.5m
        │              │
        ├──────────────┤  ← 1층 바닥 슬래브 (두께 0.5m)
────────┴──────────────┴──── 지면
```

- **배치 대상별 그리드 스냅 방식**이 다르다(3장에서 피스별로 상세 정의):
  - **셀 중심(Cell Center)**: 바닥, 계단 — 1m×1m 셀 자체를 채움.
  - **그리드 엣지(Grid Edge)**: 벽, 문 — 인접한 두 셀의 경계선에 배치.
  - **벽 부착(Wall Attach)**: 사다리 — 이미 배치된 벽의 안쪽/바깥쪽 면에 부착.

## 3. 건축 피스 타입

### 3.1 벽(Wall)

| 항목 | 값 |
|---|---|
| 치수 | 폭 1m(그리드 1칸) × **두께 0.5m** × 높이 2.5m |
| 배치 기준 | 그리드 엣지 |
| 회전 | 배치 시 해당 엣지의 방향에 자동 정렬(가로/세로 엣지 중 선택) |

**모서리(ㄱ자) 처리 — 자동 코너 필러 방식**

- **결정 사항**: 벽 두 개를 직각으로 이어 붙일 때 별도의 "코너 전용 피스"를 플레이어가 따로 고르게 하지 않는다. 대신, 벽이 걸쳐 있는 그리드 **정점(vertex)** 마다 0.5m×0.5m×2.5m 크기의 **코너 필러(Corner Pillar)** 를 시스템이 자동으로 생성해 벽 두께(0.5m)만큼의 빈틈을 채운다.
  - 벽 하나만 있어도 양 끝에 필러가 붙어 마감이 깔끔하다.
  - 여러 벽이 같은 정점을 공유하면(ㄱ자, ㄷ자, ㅁ자, +자 등 어떤 각도든) 필러 하나를 공유하고 중복 생성하지 않는다.
  - 그 정점에 연결된 벽이 모두 철거되면 필러도 자동으로 함께 제거된다.
  - 이 방식을 채택한 이유: 벽 메시 자체를 늘리거나(마이터 컷) 다양한 각도별 코너 프리팹을 미리 다 만들어두는 것보다 구현이 단순하고, 임의의 각도 조합에서도 항상 안전하게 맞물린다.

```
평면도 (위에서 본 모습, □ = 코너 필러 0.5×0.5)

□━━━━━━□
┃       ┃
┃  방   ┃
┃       ┃
□━━━━━━□
```

### 3.2 바닥(Floor)

| 항목 | 값 |
|---|---|
| 치수 | 1m × 1m × **두께 0.5m** |
| 배치 기준 | 그리드 셀 중심 |
| 지지 조건 | 지면 위, 또는 아래층 벽/필러 위에만 배치 가능(9장) |

### 3.3 계단(Stairs)

| 항목 | 값 |
|---|---|
| 치수 | 폭 1m(그리드 1칸) × 진행방향 **3칸(3m)** × 총 상승 3.0m |
| 배치 기준 | 셀 중심, 진행방향으로 3칸 연속 점유 |
| 상승률 | 칸당 1.0m 상승 × 3칸 = 3.0m — **한 층 높이(3.0m)와 정확히 일치** |

- **결정 사항**: 계단 하나가 정확히 한 층을 커버하도록 진행방향 3칸 고정 길이로 설계한다 — 계단 길이를 자유롭게 늘였다 줄였다 할 수 있게 하면 층 사이가 딱 맞물리지 않는 경우가 생겨 위층 바닥과의 정합성이 깨진다.
- 계단 아래 공간은 비워두거나(개방형) 벽/저장공간으로 활용 가능(추가 규칙 없음, 플레이어 자유).

### 3.4 사다리(Ladder)

| 항목 | 값 |
|---|---|
| 치수 | 폭 1m × 높이 **3.0m**(층 높이 전체) |
| 배치 기준 | 기존에 배치된 벽의 앞면(또는 외벽 바깥면)에 부착 |
| 이동 | Interact 없이 벽 근접 시 자동으로 오르기 시작(오르는 중 별도 조준/사격 제한은 후속 전투 밸런싱에서 검토) |

- 계단 대비 바닥 점유가 없어 좁은 공간에 유리하지만, 오르는 동안 방향 전환이 제한적이라 전투 중 취약하다는 트레이드오프를 의도적으로 남긴다.

### 3.5 문(Door)

| 항목 | 값 |
|---|---|
| 치수 | 벽과 동일(폭 1m × 두께 0.5m × 높이 2.5m) |
| 배치 기준 | 그리드 엣지 — **벽 슬롯을 대체**하는 형태로 배치(벽이 있던 자리에만 문을 놓을 수 있음, 또는 처음부터 문으로 배치) |
| 조작 | [캐릭터조작설계](./기획문서_캐릭터조작설계.md)의 `Interact`(F)로 여닫기 |
| 통행 | 닫힘 상태에서는 벽과 동일하게 차단, 열림 상태에서는 플레이어/적 모두 통과 가능(NavMesh 연동은 11장) |

## 4. 내구도(HP) & 파괴

- 모든 피스는 `maxHP`를 가진다. 적의 공격(투사체, 근접, 폭발 등 기존 [무기전투조작설계](./기획문서_무기전투조작설계.md)의 피해 판정)이 피스에 명중하면 `currentHP`가 감소하고, 0이 되면 파괴되어 사라진다.
- **결정 사항**: 파괴된 피스는 자동으로 제거되고, 그 피스에 의존하던 상위 구조(예: 벽 파괴 시 그 벽에 붙어있던 사다리, 벽이 지지하던 위층 바닥)는 **연쇄 검증**을 거쳐 지지 조건(9장)을 잃으면 함께 파괴된다 — 벽만 부수면 안전하게 2층으로 침투할 수 있는 구조적 약점을 의도적으로 남겨, 방어 설계 자체가 전략적 고민거리가 되게 한다.
- 코너 필러도 자체 HP를 가지며, 필러가 파괴되면 그 정점에 연결된 모든 벽이 지지를 잃어 함께 무너진다(필러가 구조적 급소가 되도록 의도).

---

## 5. 건축 자원

- 모든 `BuildPieceData`는 `buildCost`(소모 재료 목록)를 가진다. 배치 확정 시 인벤토리에서 재료를 차감하고, 부족하면 배치가 거부된다(8.3절 유효성 검사에 포함).
- **결정 사항**: 재료는 새 화폐/자원 시스템을 만들지 않고, [상점시스템설계](./기획문서_상점시스템설계.md) 4장의 구매(Buy) 탭에 건축 재료(목재, 금속판 등)를 일반 아이템처럼 등록해 조달할 수 있게 한다 — 이미 확립된 "새 탭을 만들지 않고 기존 카탈로그에 아이템처럼 추가" 패턴을 그대로 재사용.
- 철거(Demolish, 7장) 시 재료를 일부 환급할지 여부는 14장 권장 사항으로 남긴다.

---

## 6. 건축 모드 진입 — Player 맵 서브모드

- **결정 사항**: 새 액션 `ToggleBuildMode`(키: **T**, Press 토글)를 `Player` 맵에 추가한다. 건축 모드에 진입하면 전투 액션 일부가 건축 액션으로 **재해석**되고, 이동 관련 액션(Move/Look/Jump/Crouch/Sprint/Lean/FreeLook)은 그대로 유지된다(건축 중에도 자유롭게 돌아다닐 수 있어야 하므로).
- 건축 모드 중에는 `Fire`/`AimToggle`/`Shoulder`가 비활성화되어 오발 사고가 나지 않는다.

### 6.1 입력 재해석 표

| 물리 입력 | 전투 모드 의미 | 건축 모드 의미 |
|---|---|---|
| LMB | `Fire`(발사) | `PlacePiece` — 고스트 위치에 배치 확정 |
| RMB | `AimToggle`/`Shoulder`(조준) | `DemolishPiece` — 조준 중인 아군 건축물 철거 |
| 마우스 휠 | `AimZoomAdjust`/`WeaponCycle` | `RotatePiece` — 고스트를 90° 단위 회전 |
| `1`~`5` | `WeaponSlot1~4`(무기 슬롯) | 건축 피스 카테고리 선택 — `1`=벽, `2`=바닥, `3`=계단, `4`=사다리, `5`=문 |
| `T` | (해당 없음) | 건축 모드 종료(다시 누르면 토글) |

- **결정 사항**: 무기 슬롯은 4개(`1~4`)뿐이지만 건축 피스는 5종이므로, 건축 모드에서만 유효한 `5`번 키를 `Player` 맵에 추가한다(다른 어떤 액션과도 겹치지 않는 빈 키).
- `DemolishPiece`(RMB)는 아군이 직접 지은 구조물에만 반응하도록 레이캐스트 대상을 "Buildable" 태그로 한정한다 — 적/지형에 우클릭해도 아무 일도 일어나지 않는다.

## 7. 프리뷰(고스트) & 자석 스냅

### 7.1 레이캐스트 기준

- 카메라 조준 방향(화면 중앙, [크로스헤어탄퍼짐설계](./기획문서_크로스헤어탄퍼짐설계.md)의 조준 레이와 동일한 축이지만 탄 발사가 아닌 **배치 전용 레이캐스트**)으로 씬을 검사한다.
- 레이가 지형/기존 구조물에 닿은 지점을 현재 선택된 피스의 `snapMode`(2장)에 따라 가장 가까운 그리드 위치로 반올림한다 — "자석처럼" 달라붙는 느낌은 이 반올림 스냅에서 나온다.
- **결정 사항**: 배치 가능 거리는 플레이어로부터 **최대 5m**로 제한한다 — 멀리서 저격하듯 구조물을 짓는 것을 막아, 건축이 "지금 이 자리를 방어한다"는 전술적 행위로 남게 한다.

### 7.2 고스트 셰이더

- **결정 사항**: [셀셰이딩그래픽설계](./기획문서_셀셰이딩그래픽설계.md)의 툰/해칭 셰이더를 재사용하지 않고, 별도의 경량 **Unlit 반투명 셰이더(`BuildGhost`)** 를 사용한다 — 고스트는 씬 조명(어두운 실내 등)과 무관하게 항상 또렷하게 보여야 하는 UI에 가까운 요소이기 때문에, 조명에 영향받는 툰 셰이딩과 분리한다.
- 색상: 배치 가능 시 반투명 초록, 배치 불가 시 반투명 빨강. 가장자리에 약한 프레넬(Fresnel) 강조를 줘 형태를 더 잘 읽히게 한다.
- 상태 전환(가능↔불가능) 시 색이 즉시 스냅되지 않고 짧게(0.1초) 보간 — 이 시리즈에서 반복해온 "즉시 스냅 금지, 짧게 보간" 원칙과 통일.

### 7.3 유효성 검사 (초록/빨강 판정 기준)

고스트가 다음 조건을 모두 만족해야 "배치 가능(초록)"으로 표시된다.

1. **겹침 없음**: 다른 피스/오브젝트와 물리적으로 겹치지 않음.
2. **자원 충분**: 인벤토리에 `buildCost`만큼의 재료 보유.
3. **지지 조건 충족**: 9장의 인접 규칙을 만족.
4. **사거리 내**: 7.1절의 5m 이내.

하나라도 어긋나면 고스트는 빨강으로 표시되고, `PlacePiece` 입력은 조용히 무시된다(경고 팝업 없이 — 이 시리즈의 "실수 방지는 조용히 막고, 필요한 만큼만 피드백" 원칙과 동일).

---

## 8. 회전(Rotate)

- 벽/문: 그리드 엣지 방향(가로/세로) 중 레이 각도에 따라 자동 결정되므로, 수동 회전은 "안쪽 면 / 바깥쪽 면"(경첩 방향, 도어 스윙 방향) 전환에만 사용.
- 계단: 진행 방향(4방위) 전환에 `RotatePiece`(마우스 휠) 사용.
- 사다리: 부착 대상 벽 면(안쪽/바깥쪽) 전환에 사용.
- 바닥: 정사각형이라 회전 의미 없음(입력 무시).

## 9. 구조 지지 규칙 (간이 버전)

- **결정 사항**: 실제 물리 기반 구조 역학(하중 분산, 붕괴 시뮬레이션)은 과도한 범위이므로 채택하지 않는다. 대신 아래의 **간단한 인접 규칙**만 검사한다.

| 피스 | 배치 가능 조건 |
|---|---|
| 바닥 | 지면 위, 또는 같은 셀 아래에 벽/코너 필러/이미 배치된 바닥이 있을 때 |
| 벽 | 자신이 걸친 두 그리드 셀 중 최소 하나의 바닥이 존재할 때 |
| 계단 | 시작 지점 셀에 바닥이 존재할 때 |
| 사다리 | 부착 대상 벽이 존재할 때 |
| 문 | 대체 대상 벽 슬롯이 이미 존재하거나, 벽과 동일한 지지 조건을 만족할 때 |

- 이 규칙은 4장의 "연쇄 파괴"와 짝을 이룬다: 배치 시점에는 지지 조건을 만족했더라도, 이후 지지 대상이 파괴되면 그 순간 조건을 다시 잃어 연쇄적으로 무너진다.

## 11. 적 AI / NavMesh 연동 지점 (후속 문서와의 접점)

- 벽/문 배치·철거 시 해당 영역의 **NavMesh를 런타임으로 재계산**(Unity NavMeshSurface의 `UpdateNavMesh` 또는 `NavMeshObstacle` carve 방식)해야 적 AI가 새로 지어진 구조물을 실제 장애물로 인식한다.
- 문은 열림/닫힘 상태에 따라 통행 가능 여부가 바뀌므로, 적 AI가 문을 "부수고 들어올지" 아니면 "닫힌 문 앞에서 멈출지"는 적 AI 설계(메인 기획서 5.2절 확장 로드맵)에서 별도로 결정해야 한다 — 본 문서는 "문은 파괴 가능한 장애물"이라는 사실만 전제로 남긴다.
- 이 절의 세부 구현(재계산 빈도, 비용 최적화 등)은 12장 후속 범위로 넘긴다.

## 13. 결정 사항 요약

- 그리드 기준 1m, 층고는 바닥(0.5) + 내부 높이(2.5) = **3.0m**로 확정. 계단은 진행방향 3칸(3m)으로 층고와 정확히 맞물리도록 고정 길이.
- 벽 두께 **0.5m**, 모서리는 개별 코너 피스 대신 **자동 코너 필러(0.5×0.5×2.5)** 로 처리 — 어떤 각도 조합에도 안전하게 맞물림.
- 벽/바닥/계단/사다리/문 **5종**으로 범위 한정.
- 구조물은 **내구도(HP)를 가지며 파괴 가능**, 지지 대상 파괴 시 **연쇄 파괴**.
- 건축 재료는 **인벤토리에서 소모**, 기존 상점 구매 탭을 통해 조달 가능(새 탭 불필요).
- 새 Action Map 없이 `Player` 맵에 `ToggleBuildMode`(T)만 추가하고, 나머지는 기존 전투 액션(LMB/RMB/휠/숫자키)을 건축 모드에서 재해석. 건축 피스가 5종이라 `5`번 키를 신규 추가.
- 고스트 프리뷰는 셀셰이딩과 분리된 **Unlit 반투명 셰이더**, 배치 가능 거리 **5m 제한**, 겹침/자원/지지조건/사거리 4가지를 모두 만족해야 배치 가능.
- 구조 지지 검증은 물리 시뮬레이션 대신 **간단한 인접 규칙**만 사용.

## 14. 추가 권장 사항

- **철거 자원 환급**: 자기 구조물을 철거(Demolish)하면 소모 재료의 일부(예: 50%)를 돌려주는 것을 권장 — 건축 실수를 고칠 때의 자원 손실 부담을 줄여준다.
- **블루프린트 저장/재사용**: 자주 쓰는 방어 구조(예: "미로형 진입로")를 템플릿으로 저장해 한 번에 찍어내는 기능을 후속 확장으로 고려.
- **건축 미리보기 사운드/이펙트**: 배치 확정 시 짧은 망치질/조립 사운드와 이펙트를 주면 액션의 무게감이 생긴다.
- **디버그 연동**: [캐릭터조작설계](./기획문서_캐릭터조작설계.md) 8장의 `ToggleColliderGizmo`(F2)에 건축물 콜라이더/지지 관계선을 함께 시각화하는 옵션을 추가하면 지지 규칙(9장) 디버깅이 수월하다.
- **다인 협동 시 소유권**: 향후 협동/멀티플레이가 추가되면 `PlacedPieceInstance.ownerId`를 활용해 타인의 구조물을 철거하지 못하게 막는 규칙이 필요 — 지금은 싱글 플레이 기준이라 범위 밖.

## 15. 후속 설계 범위

- NPC/오브젝트 상호작용 트리거 시스템(문의 `Interact` 판정 등) — 여러 문서에서 반복 언급된 공통 후속 항목.
- 인벤토리 시스템 본체 — 건축 재료 보유/차감 로직.
- 적 AI의 NavMesh 재계산 방식 및 문 대응 전략(11장에서 전제만 남김).
- 지붕/천장, 창문 등 확장 피스 타입.
- 철거 자원 환급 비율, 블루프린트 저장 기능 세부 수치.
- 건축 피스 내구도(HP) 실제 수치 밸런싱.
