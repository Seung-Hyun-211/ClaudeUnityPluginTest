# 대화 & 시네마틱 구조 설계 (텍스트 대화 / 컷씬 공통 구조)

> 마을/벙커의 NPC와 상호작용했을 때 재생되는 **텍스트 대화**와, 스토리 전달을 위한 **시네마틱(컷씬)** 을 하나의 공통 자료구조로 저작할 수 있도록 설계한 문서.
> NPC/오브젝트 상호작용 자체(감지 범위, `Interact`(F) 판정, 상호작용 가능 오브젝트 종류 등)는 **별도 문서에서 다룬다** — 본 문서는 상호작용이 시작된 **이후** 재생되는 대화/시네마틱의 구조와 UI만 다룬다.
> 작성일: 2026-09-17 — [기획문서_UI조작설계.md](./기획문서_UI조작설계.md)의 `UI` Action Map을 재사용하며, [기획문서_퀘스트UI설계.md](./기획문서_퀘스트UI설계.md)의 퀘스트 창은 본 문서의 `Event` 노드를 통해 열린다.

---

## 1. 설계 원칙

1. **대화와 시네마틱을 별개 시스템으로 만들지 않는다.** 둘 다 "시퀀스(Sequence)"라는 공통 노드 그래프로 저작하고, `isCinematic` 플래그로 프레젠테이션(4장 vs 5장)만 다르게 렌더링한다. 순수 텍스트 대화는 카메라 연출 노드가 없는 시퀀스, 풀 시네마틱은 카메라 컷 노드가 포함된 시퀀스일 뿐 — 저작 도구와 재생기를 이원화하지 않는다.
2. **시퀀스는 노드(Node)의 선형~분기 그래프**로 구성된다. 대부분의 노드는 다음 노드가 하나로 고정되고, `Choice`(플레이어 선택)와 `Branch`(조건 자동 판정)만 여러 후보 중 하나를 고른다.
3. **입력은 새 Action Map을 만들지 않는다.** [UI 맵](./기획문서_UI조작설계.md)의 `Navigate`/`Submit`/`Cancel`을 그대로 재사용해, 캐릭터/무기/시점 조작에서 이미 정립한 "Tap/Hold로 의미를 나눈다"는 관용구도 동일하게 적용한다(4.2절).
4. **본 문서는 구조와 UI에 집중**한다. NPC 인식·상호작용 트리거, 실제 Cinemachine 타임라인 세팅값, 로컬라이제이션 파이프라인, 보이스 오디오 동기화는 8장 후속 범위로 남긴다.

## 2. 시퀀스 데이터 구조

### 2.1 노드 타입

| 노드 타입 | 설명 | 주요 필드 |
|---|---|---|
| `Line` | 한 화자의 대사 한 줄 | `speakerId`, `text`, `portrait`(선택), `voiceClip`(선택), `nextNode` |
| `Choice` | 플레이어에게 여러 선택지를 제시 | `options: [{ text, nextNode, condition }]` |
| `Branch` | 조건에 따라 자동으로 다음 노드를 결정(분기) | `condition`, `nextNodeIfTrue`, `nextNodeIfFalse` |
| `Event` | 게임 상태를 바꾸는 사이드 이펙트 실행 | `eventType`, `params`, `nextNode`(또는 결과별 분기, 2.2절) |
| `CameraCut` | (시네마틱 전용) 카메라 앵글·타임라인 클립 전환 | `cameraShotId`, `blendDuration`, `nextNode` |
| `Wait` | 지정 시간 대기(연출 여백) | `duration`, `nextNode` |
| `End` | 시퀀스 종료 | — |

### 2.2 `Event` 노드 — 퀘스트 UI와의 연결 고리

| eventType | 동작 |
|---|---|
| `OpenQuestOffer(questId)` | [퀘스트UI설계](./기획문서_퀘스트UI설계.md) 3.1절의 "제안" 화면을 모달로 띄우고 시퀀스를 일시정지. 결과에 따라 `nextNodeIfAccepted`/`nextNodeIfDeclined`로 재개 |
| `OpenQuestTurnIn(questId)` | 같은 문서 3.3절의 "보상 수령" 화면을 모달로 띄움. 확인 후 `nextNode`로 재개 |
| `SetFlag(name, value)` / `GiveItem(id, count)` / `StartQuest(id)` | 모달 없이 즉시 실행 후 바로 `nextNode`로 진행(상태 변경만 하는 조용한 이벤트) |

- 모달을 여는 `Event`는 재생 상태를 `ModalPending`으로 바꾸고(3장), 모달이 닫히기 전까지 시퀀스의 `Line`/`Choice` 진행을 멈춘다.

### 2.3 시퀀스 에셋 구조 (개념)

```
DialogueSequence (ScriptableObject / 그래프 에셋)
├─ sequenceId
├─ isCinematic: bool     // true면 레터박스+CameraCut 연출 활성화(5장), false면 일반 대화창(4장)
├─ skippable: bool       // false면 6장의 스킵 자체를 막음(최초 1회 핵심 스토리 등)
├─ entryNodeId
└─ nodes: Node[]
    ├─ id, type (Line/Choice/Branch/Event/CameraCut/Wait/End)
    └─ data (타입별 필드, 2.1절)
```

## 3. 재생 상태 머신

| 상태 | 설명 | Action Map |
|---|---|---|
| `Idle` | 시퀀스 없음 | `Player` 활성 |
| `Playing` | 현재 `Line`이 타이핑 효과로 출력 중 | `UI` 활성, `Player` 비활성 |
| `WaitingForAdvance` | 출력 완료, 다음 입력 대기 | `UI` 활성 |
| `ChoicePending` | `Choice` 노드 진입, 선택지 표시 및 입력 대기 | `UI` 활성 |
| `ModalPending` | `Event`가 연 퀘스트 창 등의 결과를 기다리는 중 | `UI` 활성(모달이 입력 소비) |
| `End` | `End` 노드 도달 | `Player`로 복귀 |

- **결정 사항**: [기획문서_캐릭터조작설계.md](./기획문서_캐릭터조작설계.md) 2장의 "상태별 맵 활성화표"에 아래 행을 추가한다.

| 게임 상태 | Player | UI | Global | Debug |
|---|---|---|---|---|
| 대화/시네마틱 재생 중 | OFF | **ON** | ON | ON |

  - 기존 "컷씬/연출(조작 불가 구간)" 행(Player OFF, UI OFF)과 구분되는 이유: 본 문서의 시퀀스는 선택지·스킵 입력을 받아야 하므로 `UI` 맵이 켜져 있어야 한다. 완전히 입력을 받지 않는 연출(예: 강제 이동 시퀀스)은 기존 행을 그대로 쓴다.

## 4. 텍스트 대화 UI (`isCinematic = false`)

### 4.1 레이아웃

```
┌─────────────────────────────────────────────┐
│                                               │
│                 (게임 화면)                    │
│                                               │
│  ┌───────────────────────────────────────┐  │
│  │ [초상화]  화자 이름                       │  │
│  │  ─────────────────────────────────────  │  │
│  │  대사 텍스트 (타이핑 효과로 한 글자씩 출력)    │  │
│  │                                    ▼계속 │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

- 화면 하단 고정 대사창: 좌측 초상화 + 화자 이름, 우측 본문 텍스트, 우하단 "다음" 인디케이터(점멸 화살표 등).
- `Choice` 진입 시 대사창 **위쪽**에 선택지 리스트가 세로로 펼쳐진다. `Navigate`(상/하)로 포커스 이동, `Submit`으로 확정.

### 4.2 입력 처리 (`UI` 맵 재사용)

| 액션 | 재생 상태 | 동작 |
|---|---|---|
| `Submit` | `Playing` | 타이핑 애니메이션 즉시 완료(전체 텍스트 즉시 표시) |
| `Submit` | `WaitingForAdvance` | 다음 노드로 진행 |
| `Submit` | `ChoicePending` | 포커스된 선택지 확정 |
| `Navigate` | `ChoicePending` | 선택지 포커스 이동 |
| `Cancel` (Tap, ≤0.2초) | `WaitingForAdvance` | 대화 로그(4.3절) 열기/닫기 토글 |
| `Cancel` (Hold, ≥0.5초) | `sequence.skippable == true`인 모든 상태 | 시퀀스 전체 스킵 → `End`로 즉시 이동 |

- **결정 사항**: `Cancel`도 [무기전투조작설계](./기획문서_무기전투조작설계.md)에서 확립한 **Tap/Hold 분리 관용구**를 그대로 재사용한다 — 탭은 "대화 로그 보기", 홀드는 "전체 스킵". 조작 체계 전반에서 같은 탭/홀드 패턴을 반복 사용해 학습 비용을 낮춘다.
- `ChoicePending` 상태에서는 `Cancel` Hold가 여전히 유효하지만(스킵 가능 시퀀스라면), 짧은 탭은 아무 동작도 하지 않는다 — 선택지 화면에서 "로그 보기"로 오해될 소지를 없애기 위함.

### 4.3 대화 로그(히스토리)

- 지금까지 출력된 `Line`을 스크롤 가능한 리스트로 다시 볼 수 있는 보조 패널. 새로운 게임 상태 전이 없이 대사창 위에 오버레이로만 뜬다(재생 상태 머신에 영향 없음).

## 5. 시네마틱(컷씬) UI (`isCinematic = true`)

### 5.1 레이아웃

```
┌─────────────────────────────────────────────┐
│███████████████████████████████████████████████│ ← 레터박스(상단)
│                                               │
│                 (컷씬 화면)                    │
│                                               │
│              자막: 대사 텍스트                  │
│███████████████████████████████████████████████│ ← 레터박스(하단)
└─────────────────────────────────────────────┘
```

- 진입 시 상하 레터박스 바가 약 0.3초에 걸쳐 슬라이드 인, 종료 시 슬라이드 아웃.
- **결정 사항**: 대사는 4장의 하단 고정창 대신 **화면 하단 중앙 자막 스타일**(초상화 없이 텍스트만, 더 얇고 영화적인 폰트/여백)로 표시한다 — 일반 대화 UI와 시각적으로 명확히 구분해 "지금은 연출 중"임을 직관적으로 전달하기 위함.
- `CameraCut` 노드 처리 시 자막이 짧게 페이드 아웃/인 되며 카메라 전환 타이밍과 맞춘다(급격한 텍스트 전환으로 인한 혼란 방지).

### 5.2 스킵 UX

- 화면 우측 하단에 "홀드하여 건너뛰기" 인디케이터(원형 게이지가 차오르는 연출)를 상시 노출한다. `Cancel` Hold(4.2절, 0.5초)와 연동되어 게이지가 다 차면 즉시 `End`.
- `skippable = false`인 시퀀스(최초 1회 재생되는 핵심 스토리 등)에서는 이 인디케이터 자체를 표시하지 않아, 스킵 불가 상태를 UI로도 명확히 안내한다.

## 6. 결정 사항 요약

- 대화와 시네마틱은 **공통 시퀀스(노드 그래프) 구조**로 통합 저작하고, `isCinematic` 플래그로 프레젠테이션만 분기.
- `Event` 노드가 [퀘스트UI설계](./기획문서_퀘스트UI설계.md)의 모달(제안/보상수령)을 열고, 결과에 따라 시퀀스가 분기·재개되는 구조로 두 시스템을 연결.
- 입력은 **새 Action Map 없이 기존 `UI` 맵 재사용**. `Cancel`은 기존에 확립된 **Tap(로그 보기)/Hold(전체 스킵)** 패턴을 그대로 따름.
- 게임 상태표에 "대화/시네마틱 재생 중"(Player OFF, UI ON) 행을 신설해 기존 "완전 비조작 컷씬" 행과 구분.
- 시네마틱은 **레터박스 + 하단 중앙 자막**으로, 일반 대화는 **하단 고정 대사창(초상화 포함)** 으로 시각적으로 명확히 구분.
- 시퀀스 단위로 `skippable` 플래그를 둬 핵심 스토리 시퀀스는 스킵 자체를 차단 가능.

## 7. 추가 권장 사항

- **타이핑 속도 옵션**: 접근성을 위해 텍스트 출력 속도(글자/초) 또는 "즉시 표시" 옵션을 설정 화면에 제공할 것을 권장.
- **화자 강조 연출**: 시네마틱이 아닌 일반 대화에서도, 현재 말하는 NPC를 카메라가 살짝 포커스하거나 화면 비네팅으로 강조하는 경량 연출을 `Line` 노드에 선택적 필드(`focusTarget`)로 추가하는 것을 권장 — 완전한 `CameraCut` 없이도 대화에 생동감을 줄 수 있음.
- **로컬라이제이션 대비**: `Line.text`는 원문 문자열이 아니라 **로컬라이제이션 키**로 저장하고 런타임에 현재 언어 테이블에서 조회하는 구조를 초기부터 채택할 것을 권장(후속 파이프라인 문서에서 구체화).
- **선택지 조건부 표시**: `Choice.options[].condition`을 활용해 이전 플레이 이력(플래그, 아이템 보유, 완료한 퀘스트 등)에 따라 특정 선택지가 숨겨지거나 추가되는 구조를 권장 — 대화의 반복 플레이 가치를 높임.
- **디버그 연동**: [캐릭터조작설계](./기획문서_캐릭터조작설계.md) 8장의 개발자 콘솔(`F1`)에서 임의의 `sequenceId`를 즉시 재생/점프하는 명령을 지원하면 대화 QA가 훨씬 수월해진다.

---

## 8. 후속 설계 범위

- NPC/오브젝트 상호작용 트리거 시스템(감지 범위, `Interact`(F) 판정, 상호작용 가능 오브젝트 목록) — 별도 문서.
- 실제 카메라 연출 세부(Cinemachine Timeline 트랙 구성, `CameraCut`의 `cameraShotId` 관리 방식).
- 로컬라이제이션 파이프라인(텍스트 키 관리 도구, 보이스 오디오 동기화).
- 대화 저작 툴(에디터 확장 UI) — 노드 그래프를 시각적으로 편집하는 도구.
