# 상점 시스템 설계 (구매 · 판매 · 교환 · 강화)

> NPC와의 대화 중 특정 `Event` 노드에 도달했을 때 열리는 **상점 UI**를 설계한다. [기획문서_퀘스트UI설계.md](./기획문서_퀘스트UI설계.md)가 `OpenQuestOffer`/`OpenQuestTurnIn` 이벤트로 퀘스트 창을 열었던 것과 동일한 패턴으로, 본 문서는 `OpenShop(shopId)` 이벤트로 상점 창을 연다.
> NPC/오브젝트 상호작용 트리거 자체(감지 범위, `Interact`(F) 판정)와 인벤토리 시스템 본체는 **별도 문서에서 다룬다** — 본 문서는 상점 UI의 화면 구성·흐름·최소 데이터만 다룬다.
> 작성일: 2026-09-17 (최종 수정: 2026-09-17) — **7장(강화)은 [기획문서_부적제단시스템설계.md](./기획문서_부적제단시스템설계.md)로 대체되었다.** 상점의 "강화" 탭은 이제 무기 재료 강화가 아니라 부적 장착 화면을 여는 진입점이다.

---

## 1. 설계 원칙

1. **상점은 새로운 상호작용 수단을 만들지 않는다.** [기획문서_대화시네마틱구조설계.md](./기획문서_대화시네마틱구조설계.md)의 `Event` 노드에 `OpenShop(shopId)` 타입을 추가하는 것으로 충분하다 — NPC가 상인이면 대화 그래프 어딘가(보통 인사 직후)에 이 이벤트를 배치해 바로 상점을 연다.
2. **입력은 새 Action Map 없이 기존 `UI` 맵을 재사용**한다([기획문서_UI조작설계.md](./기획문서_UI조작설계.md)). 수량 조절처럼 UI 맵에 없는 세부 조작은, [기획문서_무기전투조작설계.md](./기획문서_무기전투조작설계.md)에서 확립한 "같은 물리 입력을 컨텍스트에 따라 다르게 해석" 패턴을 그대로 따른다(`ScrollWheel` → 수량 스텝퍼).
3. **구매/판매/교환/강화는 하나의 상점 창 안의 탭**으로 통합하되, NPC(상점) 종류에 따라 필요한 탭만 노출한다 — 잡화상은 구매/판매만, 대장장이는 판매/강화만 갖는 식으로 재사용 가능한 하나의 UI 골격을 쓴다.
4. **인벤토리·화폐 시스템 본체는 범위 밖**이다. 상점 UI가 무엇을 그리고 어떤 순서로 확인창을 띄우는지만 정의하고, 실제 재화 차감/아이템 지급 로직은 인벤토리 시스템(후속 문서)의 책임으로 남긴다.

---

## 2. 진입 경로

| 경로 | 트리거 | 결과 |
|---|---|---|
| 대화 중 `Event: OpenShop(shopId)` | 상인 NPC와의 대화 그래프가 이 노드에 도달 | 상점 창을 모달로 오픈, 대화 시퀀스는 `ModalPending` 상태로 일시정지([대화시네마틱구조설계](./기획문서_대화시네마틱구조설계.md) 3장과 동일 패턴) |
| 상점 창 닫힘(`Cancel` 또는 "나가기" 버튼) | 플레이어가 거래를 마침 | 대화가 열려 있던 노드였다면 지정된 `nextNode`로 복귀(예: "또 오게" 인사 대사로 이어짐), 대화 없이 독립적으로 연 경우 그대로 게임플레이로 복귀 |

- 별도의 "상점 저널"이나 상시 열람 창은 없다 — 상점은 항상 해당 상인과 상호작용 중일 때만 열리는 모달이다(퀘스트 저널과 달리 플레이어가 임의 시점에 직접 여는 경로는 설계하지 않음, 9장 후속 범위 참고 시 필요해지면 추가).

## 3. 화면 구성 개요

```
┌─────────────────────────────────────────────┐
│ [NPC 초상화] NPC 이름           보유 골드: 1,250 │
│ ───────────────────────────────────────────  │
│  [구매] [판매] [교환] [강화]   ← TabNext/TabPrev │
│ ───────────────────────────────────────────  │
│                                               │
│              (탭별 본문, 4~7장)                 │
│                                               │
│                              [ 나가기(Cancel) ] │
└─────────────────────────────────────────────┘
```

- 상단 헤더(NPC 정보 + 보유 화폐)는 모든 탭에서 공통으로 고정 표시.
- 탭 전환은 [UI조작설계](./기획문서_UI조작설계.md)의 `TabNext`/`TabPrev`(Q/E)를 그대로 사용.
- `ShopData`에 정의된 `capability` 플래그로 활성 탭만 노출한다(4.1절).

### 3.1 상점 데이터 구조 (개념)

```
ShopData
├─ shopId
├─ capabilities: { canBuy, canSell, canExchange, canTalismanLoadout }  // NPC별로 필요한 탭만 true
├─ buyCatalog: ShopItemEntry[]        // 4장 (부적도 여기에 일반 아이템처럼 등록 가능)
├─ sellRateMultiplier: float          // 5장, 기본 0.5 (판매가 = 구매가 × 0.5)
└─ exchangeRecipes: ExchangeRecipe[]  // 6장
```

> `capabilities.canUpgrade`/`upgradeRecipes` 필드는 더 이상 사용하지 않는다(7장 참고).

## 4. 구매(Buy) 화면

```
┌─────────────────────────────────────────────┐
│  [아이콘] 아이템 A   가격 50   재고 12          │
│  [아이콘] 아이템 B   가격 120  재고 ∞           │
│  [아이콘] 아이템 C   가격 300  재고 3           │
│ ───────────────────────────────────────────  │
│  선택: 아이템 A                                │
│  수량  [ − ]  3  [ + ]   (ScrollWheel로도 조절) │
│  합계: 150 골드                                │
│              [ 구매(Submit) ]  [ 취소(Cancel) ] │
└─────────────────────────────────────────────┘
```

- `Navigate`로 목록 이동, `Submit`으로 아이템 선택 → 하단에 수량/합계 패널이 펼쳐짐.
- **수량 조절**: `ScrollWheel`(위/아래)로 1씩 증감, 보유 골드로 살 수 있는 최대치와 재고 중 작은 값으로 자동 클램프. 좌우 `Navigate`로도 동일하게 ±1(마우스 없는 게임패드 사용자 대응).
- 합계가 보유 골드를 초과하면 "구매" 버튼이 비활성(회색) 처리되고 `Submit`을 눌러도 아무 반응 없음 — 실수 구매 방지를 위해 별도 경고 팝업 없이 조용히 막는다.
- 최종 `Submit`(구매 확정) 시 즉시 처리(재확인 팝업 없음) — 퀘스트의 "포기하기"처럼 되돌릴 수 없는 손해가 큰 행동이 아니므로 굳이 재확인 단계를 넣지 않는다.

### 4.1 재고(Stock)

- **결정 사항**: 기본은 **무한 재고**(`stock = -1`)로 두고, 특정 희귀 아이템만 `ShopItemEntry`에 `stock` 값과 `restockIntervalHours`(예: 24시간)를 지정해 제한 재고 + 주기적 리필을 지원한다 — 모든 아이템에 재고 관리를 강제하면 초반 콘텐츠 제작 비용이 커지므로, 필요한 아이템에만 선택적으로 적용.

## 5. 판매(Sell) 화면

```
┌─────────────────────────────────────────────┐
│  (플레이어 인벤토리 목록)                        │
│  [아이콘] 아이템 X  보유 5   판매가 25/개         │
│  [아이콘] 아이템 Y  보유 1   판매가 60/개         │
│ ───────────────────────────────────────────  │
│  선택: 아이템 X                                │
│  수량  [ − ]  2  [ + ]   (ScrollWheel)         │
│  합계: 50 골드                                 │
│              [ 판매(Submit) ]  [ 취소(Cancel) ] │
└─────────────────────────────────────────────┘
```

- 목록은 상점 카탈로그가 아니라 **플레이어 인벤토리**를 표시(인벤토리 조회는 후속 문서의 API를 가정).
- 개별 아이템마다 판매가를 따로 정의하지 않는다. **결정 사항**: 판매가 = 해당 아이템의 기준 구매가(`ShopItemEntry.price` 또는 아이템 자체의 기본 가치) × `ShopData.sellRateMultiplier`(기본 0.5) — 데이터 입력 비용을 줄이고 "상점마다 판매율이 다르다"는 확장 여지도 남긴다.
- 장착 중인 장비, 퀘스트 아이템 등 판매 불가 아이템은 목록에서 흐리게 표시하고 선택 자체를 막는다.
- 퀘스트 문서의 "포기하기"와 달리 판매도 재확인 팝업 없이 즉시 처리(구매와 동일한 이유).

## 6. 교환(Exchange) 화면

```
┌─────────────────────────────────────────────┐
│  [재료 아이콘] 파편 x10   →   [아이콘] 강화석 x1  │
│  [재료 아이콘] 파편 x30   →   [아이콘] 희귀 재료  │
│ ───────────────────────────────────────────  │
│  선택 레시피: 파편 x10 → 강화석 x1               │
│  보유: 파편 24개 (교환 가능 2회)                  │
│  수량  [ − ]  1  [ + ]   (ScrollWheel)          │
│              [ 교환(Submit) ]  [ 취소(Cancel) ] │
└─────────────────────────────────────────────┘
```

- 골드가 아니라 **아이템 ↔ 아이템**(또는 특수 재화 ↔ 아이템)을 맞바꾸는 화면. 레벨 디자인상 "필드에서 주운 잡템을 상위 재료로 바꿔주는" 상인, 이벤트 화폐 교환소 등에 사용.
- `ExchangeRecipe { costItems: [{id, count}], resultItems: [{id, count}] }` 구조로 정의 — 구매/판매와 달리 골드 개념이 아예 없을 수 있으므로 별도 자료구조로 분리했다(4~5장의 `price` 필드를 억지로 재사용하지 않음).
- 수량 조절은 구매/판매와 동일하게 `ScrollWheel`, 보유량 기준으로 "몇 회 교환 가능한지" 자동 계산해 상한 클램프.

---

## 7. 강화(Upgrade) 탭 — 부적 장착 화면으로 대체 (변경됨)

- **결정 사항(개정)**: 재료 소모형 무기 레벨업 강화는 폐기한다. "강화" 탭은 이제 플레이어가 부적(Talisman)을 장착해 버프/능력치 상승을 얻는 **부적 장착(Loadout) 화면**을 여는 진입점이다.
- 상세 레이아웃, 데이터 구조(`TalismanData`), 슬롯 확장 규칙(제단 레벨업 연동)은 [기획문서_부적제단시스템설계.md](./기획문서_부적제단시스템설계.md) 3장을 참고.
- 변경 이유: 재료 소모형 선형 강화보다, 부적을 찾고 골라 장착하는 방식이 루팅 기반 전투 루프와 더 잘 맞물리고 "이번엔 어떤 부적을 낄까"라는 반복 선택의 재미를 준다.

## 8. 입력 처리 요약

| 액션 | 공통 동작 |
|---|---|
| `Navigate` | 아이템/탭/수량 스텝퍼 간 포커스 이동 |
| `Submit` | 목록 항목 선택 → 상세 패널 오픈 / 상세 패널에서 거래 확정 |
| `Cancel` | 상세 패널 닫기(목록으로 복귀) / 목록 화면에서는 상점 전체 닫기 |
| `ScrollWheel` | 상세 패널이 열려 있을 때 수량 ±1 조절 |
| `TabNext` / `TabPrev` | 구매/판매/교환/강화 탭 전환 |

- 모두 [기획문서_UI조작설계.md](./기획문서_UI조작설계.md)에 이미 정의된 액션이며, 상점 시스템을 위해 새로 추가하는 액션은 없다.

## 9. 결정 사항 요약

- 상점은 **대화 `Event: OpenShop(shopId)`** 로만 열리는 모달 — 별도 상호작용 수단이나 상시 열람 창은 만들지 않음.
- 구매/판매/교환/강화를 **하나의 상점 창의 탭**으로 통합하고, `ShopData.capabilities` 플래그로 NPC별 필요한 탭만 노출.
- 수량 조절은 새 액션 없이 **`ScrollWheel` 재사용**(무기 조작 설계의 컨텍스트 재해석 패턴과 동일).
- 판매가는 아이템별로 별도 입력하지 않고 **구매가 × `sellRateMultiplier`(기본 0.5)** 로 자동 계산.
- 재고는 기본 **무한**, 필요한 아이템만 제한 재고 + 주기적 리필 옵션 적용.
- 교환은 골드가 아닌 **아이템 ↔ 아이템**(또는 특수 재화) 레시피로 별도 자료구조(`ExchangeRecipe`) 분리.
- **강화(개정)**: 재료 소모형 무기 레벨업을 폐기하고 **부적 장착 화면**으로 대체 — 세부는 [부적제단시스템설계](./기획문서_부적제단시스템설계.md) 참고.
- 구매/판매 확정 시 재확인 팝업 없이 즉시 처리(퀘스트의 "포기하기"류 파괴적 행동과 달리 되돌릴 수 없는 손해가 크지 않다고 판단해 마찰을 최소화).

## 10. 추가 권장 사항

- **평판/할인 시스템**: 특정 NPC와의 우호도(퀘스트 완료 이력 등)에 따라 구매가 할인/판매가 우대를 적용하는 확장을 고려 — `ShopData`에 `reputationDiscountCurve` 같은 필드를 추가하는 방향.
- **구매/판매 확인 사운드·이펙트**: 거래 확정 시 짧은 사운드와 골드 카운터 애니메이션(숫자가 굴러가듯 변하는 연출)을 권장 — 재확인 팝업이 없는 대신, 즉각적인 피드백으로 "거래가 실제로 일어났다"는 확신을 준다.
- **교환소 특수 화폐**: 이벤트/시즌 콘텐츠를 고려해 골드와 별개의 "이벤트 코인" 같은 보조 화폐를 `ExchangeRecipe`의 `costItems`에 아이템처럼 취급해 넣을 수 있도록 이미 설계되어 있음(별도 화폐 시스템 불필요, 재료 아이템처럼 관리하면 됨) — 이 점을 인벤토리 시스템 설계 시 참고할 것.
- **디버그 연동**: [캐릭터조작설계](./기획문서_캐릭터조작설계.md) 8장의 개발자 콘솔(F1)에서 골드/재료를 즉시 지급하는 치트 명령을 지원하면 상점 QA가 수월하다.

## 11. 후속 설계 범위
