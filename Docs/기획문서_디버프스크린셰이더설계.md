# 디버프 스크린 셰이더 파이프라인 설계

> 출혈(Bleeding), 뇌진탕(Concussion) 등 상태이상(디버프)을 화면 전체에 적용되는 **포스트 프로세싱 스크린 셰이더**로 표현하기 위한 파이프라인을 설계한다.
> 핵심 목표는 "디버프가 늘어날 때마다 새 셰이더를 또 만드는" 구조가 아니라, **하나의 통합 풀스크린 셰이더 + 데이터 기반 파라미터**로 여러 디버프를 동시에 얹을 수 있는 구조를 만드는 것이다.
> 디버프 자체의 게임플레이 로직(피해량, 지속시간, 스택 규칙)과 실제 셰이더 코드 구현은 **범위 밖**이며, 본 문서는 **파이프라인 구조와 파라미터 합성 규칙**을 다룬다.
> 작성일: 2026-09-17 (최종 수정: 2026-09-17) — [기획문서_셀셰이딩그래픽설계.md](./기획문서_셀셰이딩그래픽설계.md)의 월드 셰이딩 이후, UI 렌더링 이전 단계에 삽입된다(6장).
> **개정**: 이펙트를 "지각 왜곡형"과 "피해 피드백형" 두 유형으로 나누고, 피해 피드백형은 화면 중앙(조준 영역)을 비워 시야를 가리지 않도록 설계를 보강했다(1.5절, 3.1절).

---

## 1. 설계 원칙

1. **디버프마다 별도 셰이더/패스를 만들지 않는다.** 모든 디버프는 공통 파라미터 세트(2장)에 값을 기여하는 "기여자(Contributor)"로만 존재하고, 실제 렌더링은 단 하나의 풀스크린 셰이더가 담당한다 — 새 디버프 추가 = 새 데이터 프로파일 정의이지, 새 셰이더 작성이 아니다.
2. **여러 디버프가 동시에 걸려도 합성 규칙이 명확해야 한다.** 출혈 + 뇌진탕이 동시에 걸렸을 때 각 파라미터(비네트, 블러, 색수차 등)가 어떻게 합쳐지는지 3장에서 채널별로 규정한다.
3. **월드에는 적용하되 UI에는 적용하지 않는다.** 크로스헤어·퀘스트창 등 UI 요소가 블러/색수차로 흐려지면 안 되므로, 렌더 삽입 지점을 UI보다 반드시 앞에 둔다(6장).
4. **접근성을 기본값으로 취급한다.** 화면 왜곡 계열 효과는 일부 플레이어에게 멀미를 유발할 수 있으므로, 전역 강도 배율 옵션을 처음부터 설계에 포함한다(7장).
5. **"초점이 흐려지는 느낌"과 "피해를 알리는 신호"를 구분한다.** 뇌진탕처럼 캐릭터 자신의 지각·초점이 실제로 망가진 것을 표현하는 이펙트는 화면 중앙을 포함해 적용해도 된다(오히려 그래야 설득력 있음). 반면 출혈이나 일반 피격처럼 "당신이 피해를 입었다"는 상태 정보 전달이 목적인 이펙트는 **조준·시야의 핵심 영역인 화면 중앙을 반드시 비워야** 한다 — 게임플레이(조준, 적 인식)를 방해하면서까지 정보를 전달할 필요는 없기 때문. 이 구분을 3.1절의 "이펙트 유형"으로 명문화한다.

## 2. 통합 파라미터 세트 (`ScreenEffectParams`)

모든 디버프는 아래 파라미터 중 일부에만 기여하며, 나머지는 기본값(0 또는 무효과)을 유지한다.

| 파라미터 | 범위 | 의미 |
|---|---|---|
| `vignetteColor` | Color | 화면 가장자리를 물들이는 색상 |
| `vignetteIntensity` | 0~1 | 비네트(가장자리 어둡게/물들임) 강도 |
| `desaturation` | 0~1 | 채도 감소량 |
| `colorTint` | Color | 화면 전체에 얹히는 색 보정 |
| `blurAmount` | 0~1 | 화면 흐림 정도 |
| `chromaticAberration` | 0~1 | 색수차(RGB 채널 어긋남) 강도 |
| `distortion` | 0~1 | UV 뒤틀림(파도/이중시야 느낌) 강도 |
| `pulseFrequency` / `pulseAmplitude` | Hz / 0~1 | 심장박동처럼 주기적으로 강도가 맥동하는 효과 |
| `effectCategory` | enum { `Perceptual`, `DamageFeedback` } | 3.1절 참고 — 화면 중앙까지 적용할지, 가장자리 링으로 한정할지 결정 |

## 3. 다중 디버프 합성 규칙

### 3.1 이펙트 유형과 중앙 안전 영역(Center Safe Zone)

디버프마다 `effectCategory`를 지정해, 렌더링 시 화면 중앙을 포함할지 여부를 결정한다.

| 유형 | 적용 범위 | 해당 디버프 예시 |
|---|---|---|
| `Perceptual`(지각 왜곡형) | 화면 전체(중앙 포함) — 캐릭터의 실제 시야/초점이 망가졌다는 설정이므로 중앙을 가려도 설득력 있음 | 뇌진탕(4.2절) |
| `DamageFeedback`(피해 피드백형) | **중앙 안전 영역(Center Safe Zone)을 제외한 가장자리 링(ring)에만 적용** — 조준선이 있는 화면 중앙은 절대 가리지 않음 | 출혈(4.1절), 일반 피격 방향 표시(4.3절) |

- **결정 사항**: `DamageFeedback` 유형은 파라미터 값과 무관하게, 셰이더 단계에서 아래의 **반경 마스크(Radial Mask)** 를 모든 기여 파라미터(비네트, 색조, 블러, 색수차, 왜곡 전부)에 곱해서 적용한다.

```hlsl
float RadialMask(float2 uv, float2 screenCenter, float innerSafeRadius, float outerRadius)
{
    float dist = distance(uv, screenCenter); // 화면 짧은 변 기준 정규화 거리
    return smoothstep(innerSafeRadius, outerRadius, dist); // innerSafeRadius 안쪽은 0(완전 클리어)
}
```

- **결정 사항**: `innerSafeRadius`/`outerRadius`는 디버프마다 다르게 두지 않고 **전역 상수**(예: `innerSafeRadius = 0.3`, `outerRadius = 0.6`, 화면 짧은 변의 절반을 1로 정규화)로 고정한다 — 디버프마다 안전 영역 크기가 들쭉날쭉하면 "화면 중앙은 항상 안전하다"는 플레이어의 학습된 기대가 깨지기 때문. 크로스헤어와 조준 시 시선이 머무는 영역을 기준으로 `innerSafeRadius` 값을 정하고, 설정 화면에서 접근성 옵션으로 살짝 키울 수 있게 하는 것을 권장(7장).
- 렌더링 시 두 레이어로 나눠 순차 합성한다: **① `Perceptual` 레이어**(마스크 없이 전체 화면 적용) → **② `DamageFeedback` 레이어**(위 `RadialMask`를 곱해 가장자리에만 적용). 두 레이어 모두 3.2절의 합성 규칙으로 각자 내부에서 먼저 합쳐진 뒤 최종적으로 화면에 순서대로 얹힌다.

### 3.2 다중 디버프 합성 규칙 (그룹별)

**같은 `effectCategory` 안에서** 여러 디버프가 동시에 활성화되면, 각 디버프가 기여하는 `ScreenEffectParams`를 아래 규칙으로 하나로 합친다(서로 다른 카테고리끼리는 3.1절처럼 별도 레이어로 분리되어 섞이지 않는다).

| 파라미터 그룹 | 합성 방식 | 이유 |
|---|---|---|
| `vignetteIntensity`, `chromaticAberration` | **합산 후 클램프**(`saturate(sum)`) | 여러 디버프가 겹치면 더 심각해지는 게 자연스러움. 클램프로 화면이 완전히 안 보이게 되는 것은 방지 |
| `blurAmount`, `distortion` | **최댓값 + 보조항** (`max(a,b) + min(a,b) * 0.25`) | 흐림/왜곡을 단순 합산하면 비현실적으로 과해짐. 가장 심한 디버프가 지배하되, 겹쳤을 때 "더 심하다"는 신호는 소폭 남긴다 |
| `desaturation` | **최댓값** | 채도는 한 번만 깎이면 충분 — 두 디버프가 겹쳤다고 두 배로 깎을 이유가 없음 |
| `colorTint`, `vignetteColor` | **강도 가중 평균**(각 디버프의 기여 강도를 가중치로 색을 블렌딩) | 출혈(빨강)과 중독(초록)이 동시에 걸렸을 때 단순 합산하면 탁한 색이 되어 어떤 디버프인지 읽히지 않음. 더 강한 디버프의 색이 우세하도록 가중 평균 |
| `pulseFrequency` | **가장 강한(=지속시간/스택이 큰) 디버프의 값을 채택** | 서로 다른 주기의 맥동이 섞이면 리듬이 뭉개져 어떤 신호인지 알 수 없게 됨 |

## 4. 디버프별 매핑 예시

### 4.1 출혈(Bleeding) — `effectCategory = DamageFeedback`

| 파라미터 | 값 |
|---|---|
| `vignetteColor` | 진한 빨강 |
| `vignetteIntensity` | 출혈 스택/중증도에 비례(0.2~0.6) |
| `pulseFrequency` | 현재 체력이 낮을수록 빨라짐(심장박동 가속 — 위기감 연출) |
| `desaturation` | 소폭(0.1) |
| 추가 오버레이 | 화면 가장자리에서 흘러내리는 핏방울 텍스처(스크롤 UV, 알파는 `vignetteIntensity`에 연동) — 4.4절 |

- **결정 사항(개정)**: 출혈은 캐릭터의 지각이 아니라 "체력이 새고 있다"는 상태 정보이므로 `DamageFeedback`으로 분류한다. 3.1절의 반경 마스크에 의해 **화면 중앙(조준 영역)에는 전혀 적용되지 않고**, 가장자리 링에서만 붉은 비네트와 핏방울 오버레이가 보인다 — 출혈 중에도 조준·교전에 지장이 없어야 하기 때문.

### 4.2 뇌진탕(Concussion) — `effectCategory = Perceptual`

| 파라미터 | 값 |
|---|---|
| `blurAmount` | 피격 직후 급격히 치솟았다가(피크) 서서히 감쇠(브리딩 블러) |
| `chromaticAberration` | 중~강 |
| `distortion` | 중 — UV를 사인파로 왜곡해 "핑 도는" 느낌 |
| `vignetteIntensity` | 강(터널 비전) |
| `desaturation` | 강(0.5 이상) |

- **결정 사항**: "이중시야(진짜 화면을 두 번 오프셋해서 렌더링)"는 GPU 비용이 크고 효과 대비 이득이 적어, **색수차 + UV 왜곡의 조합으로 대체**한다 — 저렴한 연산으로 유사한 "핑 도는" 인지적 신호를 준다는 판단.
- 뇌진탕은 `Perceptual`로 분류되어 화면 중앙까지 블러/왜곡이 걸린다 — 이는 의도된 것으로, "조준 자체가 흔들리고 잘 안 보인다"는 상태이상의 핵심 페널티이기 때문에 3.1절의 안전 영역 예외를 적용하지 않는다.

### 4.3 일반 피격 방향 표시(Directional Hit Feedback) — `effectCategory = DamageFeedback`

- 디버프는 아니지만, "피해 피드백형" 분류가 가장 분명하게 필요한 사례라 예시로 추가한다. 피격당한 방향(전/후/좌/우)에 대응하는 화면 가장자리 부분만 짧게(약 0.3초) 붉게 번쩍이는 연출 — 어느 쪽에서 공격받았는지 알려주는 용도.
- 이 효과는 항상 3.1절의 반경 마스크를 통과하므로 **애초에 중앙을 가릴 파라미터 값을 넣어도 셰이더 단계에서 자동으로 안전하게 걸러진다** — 이것이 파이프라인을 카테고리 기반으로 설계한 이유: 개별 디버프/피드백을 만들 때마다 "중앙을 가리지 않게" 값을 조심해서 넣을 필요 없이, 유형만 `DamageFeedback`으로 지정하면 안전성이 구조적으로 보장된다.

### 4.4 핏방울 오버레이(출혈 전용 보조 효과)

- 별도의 알파 텍스처(핏방울/얼룩 패턴)를 화면 상단에서 스크롤시키며, 알파 강도를 `vignetteIntensity`에 연동한다. 이 오버레이는 `ScreenEffectParams`의 공용 파라미터가 아니라 **출혈 전용 보조 텍스처 슬롯**으로 별도 취급한다 — 모든 디버프에 억지로 일반화하면 파라미터 세트가 비대해지므로, 디버프별 "커스텀 오버레이 텍스처" 슬롯 1개를 별도로 허용하는 절충안(9장 권장 참고). 이 오버레이 텍스처 역시 `DamageFeedback` 레이어에 속하므로 3.1절의 반경 마스크가 동일하게 적용되어 중앙에는 그려지지 않는다.

## 5. 데이터 구조

```
DebuffScreenEffectProfile (ScriptableObject, 디버프 종류당 1개)
├─ debuffType: enum (Bleeding, Concussion, Poison, ...)
├─ effectCategory: enum (Perceptual, DamageFeedback)   // 3.1절
├─ maxVignetteIntensity / vignetteColor
├─ maxDesaturation
├─ maxBlur
├─ maxChromaticAberration
├─ maxDistortion
├─ stackCurve: AnimationCurve   // 스택 수(또는 중증도) → 0~1 정규화 강도
├─ pulseCurve: AnimationCurve   // 시간 → 맥동 배율 (선택)
└─ overlayTexture: Texture2D?   // 4.4절 같은 전용 오버레이(선택)
```

```csharp
// 매 프레임 합성 (의사코드) — 카테고리별로 별도 레이어를 만든 뒤 마지막에 셰이더에서 다른 마스크로 합성
ScreenEffectParams perceptualLayer = ScreenEffectParams.Default;
ScreenEffectParams damageFeedbackLayer = ScreenEffectParams.Default;

foreach (var debuff in activeDebuffs)
{
    var profile = debuff.Profile;
    float intensity = profile.stackCurve.Evaluate(debuff.CurrentStackOrSeverity);
    var contribution = profile.Evaluate(intensity, Time.time); // 3.2절 표의 각 채널로 분해된 값

    if (profile.effectCategory == EffectCategory.Perceptual)
        perceptualLayer = CompositeRules.Merge(perceptualLayer, contribution);   // 3.2절 규칙
    else
        damageFeedbackLayer = CompositeRules.Merge(damageFeedbackLayer, contribution);
}

perceptualLayer.ApplyGlobalAccessibilityScale(settings.debuffEffectStrength);        // 7장
damageFeedbackLayer.ApplyGlobalAccessibilityScale(settings.debuffEffectStrength);

screenEffectMaterial.SetPerceptualParams(perceptualLayer);       // 셰이더에서 마스크 없이 전체 적용
screenEffectMaterial.SetDamageFeedbackParams(damageFeedbackLayer); // 셰이더에서 RadialMask(uv)를 곱해 적용
```

## 6. 렌더 파이프라인 삽입 지점

- URP **Full Screen Pass Renderer Feature**(또는 동등한 커스텀 Renderer Feature)로 구현하고, 삽입 시점은 **`AfterRenderingPostProcessing`**(URP 기본 포스트 프로세싱 — 블룸/컬러그레이딩 등 — 이후, UI 렌더링 이전)로 결정한다.
  - **결정 사항**: "메인 포스트 프로세싱 이전"이 아니라 "이후"를 선택한 이유 — 디버프 오버레이가 블룸/컬러그레이딩 설정값에 따라 예측 불가하게 섞이는 것을 방지하고, 항상 동일한 최종 강도로 보이도록 일관성을 우선했다.
- 이 Renderer Feature는 **월드를 그리는 Base Camera에만 부착**하고, UI 전용 Overlay Camera에는 부착하지 않는다 — [기획문서_UI조작설계.md](./기획문서_UI조작설계.md)에서 다루는 UI 요소(크로스헤어 포함, [기획문서_크로스헤어탄퍼짐설계.md](./기획문서_크로스헤어탄퍼짐설계.md))가 흐려지지 않도록 보장(1.3절 원칙).

---

## 7. 접근성

- 설정 화면([UI조작설계](./기획문서_UI조작설계.md) 3장의 "설정 화면")에 **"디버프 화면 이펙트 강도"** 슬라이더(0~100%)를 추가하고, 5장 합성 결과 전체에 곱해지는 전역 배율로 적용한다.
- 같은 설정 화면에 `DamageFeedback` 레이어의 `innerSafeRadius`(3.1절)를 키울 수 있는 **"중앙 안전 영역 크기"** 옵션을 추가하는 것을 권장 — 저시력·멀미 민감 플레이어가 안전 영역을 기본값보다 더 넓혀 중앙 주변까지 이펙트가 얼씬도 못 하게 설정할 수 있게 한다.
- **결정 사항**: 슬라이더를 0%로 내려도 `vignetteColor`처럼 "무슨 디버프가 걸렸는지 알려주는" 최소한의 신호(약한 색상 틴트 등)는 완전히 0으로 만들지 않고 일정 하한선을 두는 것을 검토 — 상태이상을 인지하지 못해 사망하는 것은 접근성이 아니라 정보 박탈이므로, UI 상의 디버프 아이콘/HUD 표시(후속 문서)와 별개로 화면 이펙트만 낮출 수 있게 한다.

---

## 8. 결정 사항 요약

- 디버프마다 셰이더를 만들지 않고, **공통 `ScreenEffectParams` + 디버프별 데이터 프로파일**로 통합 파이프라인 구성.
- **이펙트를 `Perceptual`(지각 왜곡형)과 `DamageFeedback`(피해 피드백형) 두 카테고리로 분리**하고, `DamageFeedback`은 셰이더 단계의 반경 마스크(`RadialMask`)로 화면 중앙(조준 영역)을 항상 비워 시야를 가리지 않도록 구조적으로 보장(3.1절) — 개별 디버프 파라미터 값을 아무리 세게 넣어도 카테고리만 올바르면 중앙은 안전.
- 안전 영역 반경(`innerSafeRadius`/`outerRadius`)은 디버프마다 다르게 두지 않고 **전역 상수**로 고정해 "화면 중앙은 항상 안전하다"는 일관된 기대를 유지.
- 다중 디버프 합성은 **같은 카테고리 내에서** 파라미터 그룹별로 **합산·최댓값·가중평균** 중 성격에 맞는 규칙을 채널별로 다르게 적용(3.2장), 카테고리가 다르면 별도 레이어로 분리되어 섞이지 않음.
- 출혈=`DamageFeedback`(붉은 비네트+심장박동 맥동+핏방울 오버레이, 중앙 미적용), 뇌진탕=`Perceptual`(블러+색수차+UV왜곡+강한 비네트, 중앙 포함 적용, 이중시야 대신 저비용 대체)로 매핑.
- 디버프 전용 커스텀 오버레이 텍스처는 공용 파라미터 세트에 억지로 넣지 않고 **디버프별 1개 슬롯**으로 예외 허용.
- 렌더 삽입 지점은 **URP 기본 포스트 프로세싱 이후, UI 이전**(Base Camera 전용, Overlay UI Camera 미적용).
- 접근성 슬라이더를 기본 설계에 포함하되, 상태 인지에 필요한 최소 신호는 완전히 끄지 않는 하한선을 둘 것을 권장. 중앙 안전 영역 크기도 접근성 옵션으로 조정 가능하게 함.

## 9. 추가 권장 사항

- **디버프 아이콘/HUD 연동**: 화면 이펙트와 별개로, 현재 걸린 디버프 목록을 아이콘+잔여시간 게이지로 HUD에 항상 표시할 것을 권장(접근성 백업 + 정보 명확성).
- **오디오 연동**: 뇌진탕의 이명(귀울림), 출혈의 심장박동 사운드를 `pulseFrequency`와 동기화하면 시청각이 일치해 몰입도가 올라감 — 오디오 시스템(후속 문서)과 파라미터를 공유하는 구조를 권장.
- **디버그 시각화**: [캐릭터조작설계](./기획문서_캐릭터조작설계.md) 8장의 개발자 콘솔(F1)에서 임의의 디버프를 즉시 부여/제거하고 `ScreenEffectParams` 현재 값을 오버레이로 표시하는 치트/디버그 명령을 지원하면 튜닝이 수월하다.
- **새 디버프 추가 체크리스트**: 후속 디버프(중독, 실명/플래시뱅 등)를 추가할 때는 (1) 새 셰이더가 아니라 `DebuffScreenEffectProfile` 애셋 하나만 만들면 되는지, (2) `effectCategory`를 `Perceptual`/`DamageFeedback` 중 무엇으로 둘지("이 디버프가 캐릭터의 지각 자체를 망가뜨리는가, 아니면 단순 상태 경고인가?")를 항상 먼저 검토 — 기존 파라미터로 표현이 안 되는 새로운 시각 효과가 필요할 때만 2장의 파라미터 세트 확장을 검토.
