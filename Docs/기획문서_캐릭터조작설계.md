# 캐릭터 조작 설계 (Input Action 기반)

> Unity Input System(Input Actions)을 사용한 키 입력 설계 문서.
> 캐릭터 조작 / UI 조작 / 시스템(이벤트) 조작 / 개발자 디버그 조작을 Action Map으로 분리하여, 전체화면 전환 등 항상 동작해야 하는 입력이 게임 상태에 관계없이 살아있도록 한다.
> 작성일: 2026-09-17 (최종 수정: 2026-09-17) — 본 문서는 [기획문서_시점전환슈팅게임.md](./기획문서_시점전환슈팅게임.md)의 세부 설계 문서이며, 캐릭터 조작 + 개발자 디버그 조작을 다룬다. 무기/전투 조작은 [기획문서_무기전투조작설계.md](./기획문서_무기전투조작설계.md)에서 별도로 다룬다.

---

## 1. 설계 원칙

1. **입력 컨텍스트 분리**: 캐릭터 조작(Player), UI 조작(UI), 시스템 이벤트(Global), 개발자 디버그(Debug) 4개의 Action Map으로 분리한다.
2. **맵 단위 On/Off**: 게임 상태(플레이 중 / 일시정지·메뉴 / 로딩 등)에 따라 Player·UI 맵을 서로 배타적으로 켜고 끈다. Global 맵은 게임 상태와 무관하게 항상 활성 상태를 유지한다. Debug 맵도 게임 상태와 무관하게 항상 활성이지만, **에디터/Development Build에서만 존재**하고 배포용(Release) 빌드에는 아예 포함되지 않는다(6.1 참고).
3. **한 Action Map 안에서 키 중복 금지**: 같은 맵 내에서 동일 키가 서로 다른 액션에 매핑되지 않도록 한다. 다른 맵끼리는 같은 키를 재사용할 수 있으나(예: UI가 열릴 때만 활성화되는 맵이라면), 항상 동시에 활성화될 수 있는 Global + Player 조합에서는 키 중복을 피한다.
4. **이벤트 기반 처리**: `PlayerInput` 컴포넌트는 "Invoke C# Events" 방식을 사용하고, Input Actions 에셋에서 **Generate C# Class**를 켜서 문자열 기반 `SendMessage` 대신 타입 세이프한 코드로 입력을 받는다.

## 2. Action Map 구조

| Action Map | 활성 조건 | 커서 상태 | 포함 액션(대표) |
|---|---|---|---|
| **Player** | 실제 조작 가능한 게임플레이 중 (일시정지/메뉴/대화 등이 아닐 때) | Lock + Hidden | Move, Look, Jump, Crouch, Sprint, Lean, FreeLook, Interact (본 문서 범위) / 무기·전투 액션은 [무기전투조작설계 문서](./기획문서_무기전투조작설계.md), 시점 전환(`ViewSwitch`)은 [시점전환조작설계 문서](./기획문서_시점전환조작설계.md) 참고 |
| **UI** | 일시정지 메뉴, 인벤토리, 설정 화면 등 UI가 게임을 가로챈 상태 | Visible + Unlocked | Navigate, Submit, Cancel, Point, Click, TabNext/TabPrev 등 — 세부 바인딩은 [기획문서_UI조작설계.md](./기획문서_UI조작설계.md) 참고 |
| **Global** | 항상 활성화 (게임 상태 무관, 배포 빌드에도 존재) | 영향 없음 | ToggleFullscreen, TogglePause, Screenshot 등 시스템/메타 액션 |
| **Debug** | 항상 활성화 (게임 상태 무관, **에디터/Development Build 전용**) | 모드별 상이 | ToggleDevConsole, ToggleColliderGizmo, ToggleVisionGizmo, ToggleFreeCam 등 (8장 참고) |

**상태별 맵 활성화표**

| 게임 상태 | Player | UI | Global | Debug(Dev 빌드) |
|---|---|---|---|---|
| 인게임 플레이 | ON | OFF | ON | ON |
| 일시정지 메뉴 | OFF | ON | ON | ON |
| 인벤토리/설정 화면 | OFF | ON | ON | ON |
| 컷씬/연출(조작 불가 구간) | OFF | OFF | ON | ON |
| 대화/시네마틱 재생 중 (선택지·스킵 입력 필요) | OFF | ON | ON | ON |
| 디버그 프리캠 활성 중 | ON(백그라운드 유지) | OFF | ON | ON |

> Global 맵은 항상 ON이므로, 이 맵에 배치하는 액션은 "다른 어떤 상태에서도 눌리면 반응해야 하는 입력"으로 한정한다 (전체화면 전환, 일시정지 토글 등). Debug 맵 역시 항상 ON이지만 배포 빌드에서는 아예 존재하지 않으므로 출시 빌드의 입력과 섞이지 않는다. 캐릭터 조작과 절대 겹치지 않도록 이번 문서의 4장/8장에서 키 중복을 별도 검토한다.

## 3. Player 맵 — 캐릭터 조작 액션 정의

| 액션명 | 타입 | 바인딩(키보드/마우스) | 방식 | 설명 |
|---|---|---|---|---|
| `Move` | Value / Vector2 | W/A/S/D (2D Vector Composite) | 아날로그(누르는 동안 지속) | 전후좌우 이동 입력 |
| `Look` | Value / Vector2 (Pass Through) | Mouse Delta | 아날로그, 프레임마다 delta 전달 | 카메라 피치 + 캐릭터/카메라 요(Yaw) 회전 입력 |
| `FreeLook` | Button | Left Alt | Hold(누르는 동안 true) | `Look` 입력의 적용 대상을 카메라 전용으로 전환하는 모디파이어 |
| `Jump` | Button | Space | Press(트리거 시 1회) | 점프 |
| `Crouch` | Button | C | Press → 상태 토글 | 웅크리기 On/Off |
| `Sprint` | Button | Left Shift | Hold(누르는 동안 true) | 달리기 |
| `Lean` | Value / Axis(1D) | Q(-1) / E(+1) 1D Axis Composite | Hold, 뗄 경우 0으로 복귀 | 좌/우 몸 기울이기(peek) |
| `Interact` | Button | **F** | Press(트리거 시 1회) | 상호작용(문 열기, 아이템 줍기, NPC 대화 등) — **키 확정** |

**바인딩 상세**

- `Move`: `2D Vector Composite` — Up: W, Down: S, Left: A, Right: D. (게임패드 대응 시 Left Stick을 같은 액션에 추가 바인딩)
- `Look`: 마우스는 `Delta`(누적이 아닌 프레임 이동량) 값을 그대로 사용. 감도(Sensitivity)는 X/Y 축 별도 설정 가능하도록 설계(설정 화면에서 조정, 본 문서 범위 밖).
- `Lean`: `1D Axis Composite` — Negative: Q, Positive: E. 동시에 누르면 상쇄되어 0.
- `Interact`: 이전 문서에서 `E`와 충돌 가능성이 지적되어 **`F`로 확정**했다. 상호작용 가능한 대상이 시야 내에 있을 때만 입력을 받도록(레이캐스트/트리거 기반 대상 탐지) 캐릭터 컨트롤러 쪽에서 게이팅한다.

## 4. 세부 동작 로직

### 4.1 이동 (Move)

- `Move` 벡터를 캐릭터의 로컬 전방/우측 축 기준으로 변환해 이동시킨다(카메라가 아니라 **캐릭터 몸체의 정면 기준**으로 이동 — TPS/FPS 겸용 컨트롤러이므로 몸체 축을 기준으로 통일).
- 이동 속도는 Sprint / Crouch 상태에 따라 배율이 곱해지는 구조로 설계 (기본 1.0, Sprint ×1.6, Crouch ×0.5 — 수치는 밸런싱 단계에서 조정).
- `Sprint`와 `Crouch`는 동시 성립 불가 (아래 4.4, 4.5 참고).

### 4.2 카메라/몸체 회전 (Look) vs 자유 시야 (FreeLook)

이번 조작 설계에서 가장 핵심적인 상호작용이다.

- **기본 상태 (`FreeLook` = false)**
  - Mouse X → 캐릭터 몸체(Transform)의 Yaw 회전에 직접 반영. 카메라는 캐릭터에 종속되어 함께 회전.
  - Mouse Y → 카메라 Pitch(상하 시야)에만 반영. 몸체는 Pitch의 영향을 받지 않음.
  - 즉, 평소에는 "마우스로 보는 방향 = 캐릭터가 바라보는 방향"이 항상 일치.

- **`FreeLook` = true (Left Alt를 누르고 있는 동안)**
  - Mouse X/Y 입력이 **카메라 피벗에만** 적용되고, 캐릭터 몸체 Yaw는 더 이상 갱신되지 않음(그 시점의 몸체 방향에 고정).
  - 카메라는 몸체 기준 좌우로 일정 각도(예: ±100°) 내에서 자유롭게 회전 가능 — 코너 확인, 주변 정찰 등에 사용.
  - 회전 한계를 넘기지 않도록 클램프 적용.

- **Left Alt를 뗄 때 (`FreeLook` true → false 전환 시점)**
  - 카메라가 다시 캐릭터 몸체의 정면(Yaw 오프셋 0) 방향으로 복귀.
  - **결정 사항**: 즉시 스냅이 아니라 짧은 시간(약 0.12~0.18초) 동안 부드럽게 보간하여 복귀시킨다. 이유: 순간 스냅은 시야가 급격히 튀어 어지러움(멀미)을 유발하기 쉽고, 상황 파악을 방해함. 보간 시간은 옵션값으로 노출해 추후 조정 가능하게 한다.
  - 보간 중에 다시 `FreeLook`을 누르면 즉시 자유 시야 모드로 재진입(보간 취소).

- FreeLook 중에는 `Move` 이동 방향 기준이 카메라가 아니라 **몸체 정면 기준을 그대로 유지**한다 (즉 FreeLook으로 곁눈질하며 이동해도 이동 방향이 바뀌지 않음). 이는 "관찰용 시야"와 "이동 방향"을 분리해 어지러움과 오조작을 방지하기 위함.

### 4.3 점프 (Jump)

- Grounded 판정 시에만 점프 실행.
- 입력 반응성을 위해 **점프 버퍼(Jump Buffer, 약 0.1초)** 와 **코요테 타임(Coyote Time, 약 0.1초)** 적용을 권장 — 착지 직전/직후 살짝 빗나간 입력도 점프로 인정해 조작감 개선.
- `Crouch` 상태에서 점프 시: 자동으로 Crouch 해제 후 점프할지, 점프를 막을지는 레벨 디자인에 따라 결정 — 기본안은 **Crouch 해제 + 점프 허용**.

### 4.4 웅크리기 (Crouch)

- **결정 사항**: Hold 방식이 아니라 **Press 시 토글**(C를 누를 때마다 On/Off) 방식을 채택.
  - 이유: Sprint(Shift)는 이미 Hold 방식이라 손가락 하나를 계속 누르고 있어야 하는데, Crouch까지 Hold로 하면 동시에 두 키를 누른 채 유지해야 하는 상황이 잦아져 피로도가 높음. 은엄폐 위주로 자세를 오래 유지하는 상황이 많은 슈팅 장르 특성상 토글이 더 적합.
- 웅크린 상태에서 위쪽에 장애물이 있어 일어설 수 없는 경우, 장애물이 사라질 때까지 자동으로 Crouch 상태를 유지(강제 해제 금지). 이를 위해 캐릭터 머리 위 공간 체크(Overlap/Raycast) 로직이 필요.
- `Sprint`와 `Crouch`는 동시 불가: Crouch 중 `Sprint` 입력이 들어와도 무시(또는 Crouch를 자동 해제할지는 후속 결정 필요 — 기본안은 **Crouch 중 Sprint 입력 무시**로 하여 사용자의 의도치 않은 기립을 방지).

### 4.5 달리기 (Sprint)

- Hold 방식 유지 (누르고 있는 동안만 스프린트).
- **결정 사항**: `Move` 입력이 전방(캐릭터 정면 기준 전방 반원 이내, 예: ±60° 이내) 성분을 포함할 때만 스프린트 속도 배율 적용. 순수 후진/측면 이동 중에는 Shift를 눌러도 기본 이동 속도로 취급.
  - 이유: 후방 주시 없이 전속 후퇴하는 것을 막아 슈팅 장르 특유의 포지셔닝 긴장감을 유지하기 위함(일반적인 FPS/TPS 관례를 따름).
- `FreeLook` 중에도 Sprint는 가능하지만, FreeLook의 "관찰" 목적과 상충하므로 Sprint 시작 시 FreeLook을 자동 해제할지는 후속 검토 사항으로 남긴다(본 문서에서는 강제하지 않음).

### 4.6 몸 기울이기 (Lean)

- Hold 방식: Q를 누르는 동안 좌측으로, E를 누르는 동안 우측으로 카메라(및 상체)가 기울어짐. 떼면 원상 복귀.
- 목표 기울기 각도로 즉시 스냅하지 않고 짧게 보간(예: 0.1초)하여 자연스럽게 처리.
- 이동/점프와 동시 사용 가능. 단, `Sprint` 중에는 Lean 입력을 무시(달리는 동작과 peek 동작이 애니메이션/카메라상 충돌하므로) — **결정 사항**: Sprint 중 Lean 비활성화.
- `FreeLook`과 Lean은 동시 사용 가능하도록 설계(코너에서 기울이며 자유 시야로 살짝 더 보는 조합은 자연스러운 상호작용이므로 제한하지 않음).

## 5. 키 충돌 및 예약 검토

| 검토 대상 | 내용 | 결정 |
|---|---|---|
| 전체화면 전환 키 | 흔히 `Alt + Enter` 조합을 쓰지만, `Left Alt`는 이미 `FreeLook` 모디파이어로 상시 점유됨. FreeLook을 누른 채 Enter를 누르면 의도치 않게 전체화면이 토글될 위험. | Global 맵의 전체화면 전환 키는 **F11 단독 키**로 결정 (Alt 조합 사용 금지). |
| 상호작용(Interact) 키 | 일반적으로 `E`를 사용하는 경우가 많으나, 본 설계에서 `E`는 이미 `Lean`(우측 기울이기)에 사용 중이라 충돌. | **확정**: `E` 대신 `F`를 상호작용 키로 사용 (3장 반영 완료). |
| 일시정지 키 | `Esc` | Global 맵에 `TogglePause` 배치, Player/UI 어느 상태에서도 항상 동작. |
| Crouch(C) / Sprint(Shift) | 서로 다른 키라 직접 충돌은 없으나 상태 상충(4.4 참고)이 있어 로직으로 처리. | 문제 없음, 로직으로 해결(위 4.4/4.5 참고). |
| Debug 맵 함수키(F1~F4) vs Global 함수키(F11/F12) | 모두 함수키 행을 사용하지만 서로 다른 물리 키라 겹치지 않음. | 문제 없음. Debug는 F1~F4, Global은 F11/F12로 영역을 구분해 향후 확장 시에도 헷갈리지 않게 규칙화. |
| Debug `Interact(F)` vs Debug `ToggleFreeCam` 등 함수키 | 알파벳 `F`(상호작용)와 함수키 `F1~F4`는 Input System에서 서로 다른 컨트롤(`Keyboard/f` vs `Keyboard/f1` 등)이라 물리적으로 겹치지 않음. | 문제 없음, 확인만 해두고 넘어감. |

## 6. 구현 메모 (Unity Input System)

### 6.1 Input Actions 에셋 구조 (개념)

```
InputSystem_Actions (Input Actions Asset)
├─ Action Map: Player
│   ├─ Move          <Vector2>   [WASD 2D Vector Composite]
│   ├─ Look          <Vector2>   [Mouse/delta, Pass Through]
│   ├─ FreeLook       <Button>    [Keyboard/leftAlt]
│   ├─ Jump          <Button>    [Keyboard/space]
│   ├─ Crouch        <Button>    [Keyboard/c]
│   ├─ Sprint        <Button>    [Keyboard/leftShift]
│   ├─ Lean          <Axis 1D>   [Q(-1) / E(+1) Composite]
│   └─ Interact      <Button>    [Keyboard/f]
├─ Action Map: UI
│   └─ (Input System 기본 제공 UI 액션맵 그대로 재사용: Navigate/Submit/Cancel/Point/Click 등)
├─ Action Map: Global
│   ├─ ToggleFullscreen <Button> [Keyboard/f11]
│   ├─ TogglePause      <Button> [Keyboard/escape]
│   └─ Screenshot       <Button> [Keyboard/f12]
└─ Action Map: Debug  (Editor / Development Build 전용, 8장 참고)
    ├─ ToggleDevConsole    <Button> [Keyboard/f1]
    ├─ ToggleColliderGizmo <Button> [Keyboard/f2]
    ├─ ToggleVisionGizmo   <Button> [Keyboard/f3]
    └─ ToggleFreeCam       <Button> [Keyboard/f4]
```

### 6.2 코드 연동 방침

- Input Actions 에셋에서 **"Generate C# Class"** 옵션을 켜서 `PlayerControls` 같은 생성 클래스를 사용 (문자열 기반 `SendMessage` 대신 델리게이트/이벤트로 처리해 오탈자·성능 문제 방지).
- 캐릭터 컨트롤러(예: `PlayerController`)는 `Player` 맵의 콜백만 구독, UI 매니저는 `UI` 맵만 구독, 시스템 매니저(예: `SystemInputManager`)는 `Global` 맵만 구독 — 책임을 컴포넌트 단위로도 분리한다.
- 게임 상태 매니저(`GameStateManager` 등)가 상태 전이 시 `playerInput.SwitchCurrentActionMap("UI")` / `"Player"` 형태로 맵을 전환하고, 동시에 커서 Lock/Visible 상태를 함께 갱신하는 구조를 권장 (2장 표와 1:1 대응).

### 6.3 FreeLook 처리 의사코드

```csharp
// 매 프레임(또는 Look 콜백에서) 처리하는 회전 로직 개념
void OnLook(Vector2 delta)
{
    if (isFreeLookHeld)
    {
        cameraYawOffset = Clamp(cameraYawOffset + delta.x * sensX, -maxFreeLookAngle, maxFreeLookAngle);
        cameraPitch     = Clamp(cameraPitch + delta.y * sensY, minPitch, maxPitch);
        // bodyTransform.yaw 는 갱신하지 않음
    }
    else
    {
        bodyTransform.yaw += delta.x * sensX;   // 몸체 회전
        cameraPitch = Clamp(cameraPitch + delta.y * sensY, minPitch, maxPitch);
        cameraYawOffset = 0f;                   // 평소엔 오프셋 없음(몸체와 항상 일치)
    }
}

void OnFreeLookReleased()
{
    StartCoroutine(SmoothReturnCameraYawOffsetToZero(duration: 0.15f));
}
```

## 7. 결정 사항 요약

- **Action Map 4분할**: `Player`(캐릭터) / `UI`(메뉴) / `Global`(시스템, 항상 활성, 배포 빌드 포함) / `Debug`(개발자 전용, 항상 활성이지만 Editor·Development Build에만 존재) 로 입력 컨텍스트 분리.
- **Look 처리**: 평소엔 마우스 X가 몸체 Yaw까지 회전시키고, `Left Alt`를 누르는 동안(`FreeLook`)에는 카메라만 회전하고 몸체는 고정. Alt를 떼면 약 0.15초에 걸쳐 카메라가 몸체 정면으로 부드럽게 복귀(즉시 스냅 아님).
- **FreeLook 중 이동 기준**: 카메라가 아니라 몸체 정면 기준으로 이동 방향 유지.
- **Crouch(C)**: Hold가 아닌 **토글** 방식. Sprint 중 진입 불가, Crouch 중 Sprint 입력은 무시.
- **Sprint(Shift)**: Hold 방식이며, 전방(±60° 이내) 이동 시에만 배속 적용. Sprint 중에는 Lean 비활성화.
- **Lean(Q/E)**: Hold 방식, 1D Axis Composite로 좌우 상쇄 처리. FreeLook과는 동시 사용 허용.
- **전체화면 전환 키**: `Alt+Enter` 대신 **F11 단독 키**로 결정 (Left Alt가 FreeLook에 상시 점유되어 있어 충돌 방지).
- **상호작용(Interact) 키 확정**: `E`는 `Lean`에 이미 사용 중이므로 **`F`로 확정**.
- **디버그 조작 키 확정**: `F1`(개발자 콘솔) / `F2`(콜라이더 표시) / `F3`(시야·감지범위 표시) / `F4`(프리캠, 카메라를 캐릭터에서 분리) — Debug 맵은 Editor/Development Build 전용이며 배포 빌드에서는 컴파일 단계에서 제외.
- **구현 방식**: Input Actions 에셋 + Generate C# Class, `PlayerInput.SwitchCurrentActionMap`으로 상태별 맵 전환, 커서 Lock/Visible도 함께 전환.

## 8. Debug 맵 — 개발자 디버그 조작

디버깅/QA 편의를 위한 개발자 전용 입력이다. **Editor 또는 Development Build에서만 활성화**되며(`#if UNITY_EDITOR || DEVELOPMENT_BUILD` 컴파일 가드), 실제 배포(Release) 빌드에는 Debug Action Map 자체를 포함하지 않는다. 게임 상태(Player/UI 전환)와 무관하게 항상 활성 상태를 유지한다.

### 8.1 액션 정의

| 액션명 | 타입 | 바인딩 | 방식 | 설명 |
|---|---|---|---|---|
| `ToggleDevConsole` | Button | F1 | Press → 토글 | 개발자 콘솔/디버그 메뉴 열기·닫기 (명령어 입력, 치트, 변수 조정 등의 진입점) |
| `ToggleColliderGizmo` | Button | F2 | Press → 토글 | 씬 내 모든(또는 카메라 시야 내) 콜라이더 와이어프레임 표시 On/Off |
| `ToggleVisionGizmo` | Button | F3 | Press → 토글 | 캐릭터/AI의 시야각(FOV) · 감지 반경 · 사격 레이 등 인지 관련 기즈모 표시 On/Off |
| `ToggleFreeCam` | Button | F4 | Press → 토글 | 카메라를 캐릭터에서 **분리**해 자유 비행 스펙테이터 카메라로 전환 (아래 8.3 참고) |

> `ToggleDevConsole` 이후 세부 명령(치트, 아이템 지급, 스탯 조정 등)은 콘솔 내부 텍스트 명령으로 처리하고 개별 단축키를 늘리지 않는 것을 권장 — 디버그 키가 계속 늘어나면 실수로 일반 키와 충돌할 위험이 커지기 때문.

### 8.2 콜라이더/시야 표시 (`ToggleColliderGizmo`, `ToggleVisionGizmo`)

- 각각 독립적인 On/Off 토글이며 동시에 켤 수 있다(콜라이더 + 시야를 함께 보면서 AI 감지 로직 디버깅 등에 활용).
- 구현은 Unity의 `Gizmos`/`Handles` 또는 `Debug.DrawLine` 계열을 런타임에도 그리도록 별도 `DebugDrawService` 같은 매니저를 두고, 두 토글 상태(bool)를 그 매니저가 구독하는 방식을 권장(각 컴포넌트가 직접 Input을 구독하지 않고 중앙에서 상태만 갱신 → 조회).
- 릴리스 빌드에서는 `DebugDrawService` 자체가 컴파일되지 않도록 하여 성능/보안(콜라이더·시야 범위 같은 밸런스 정보 노출 방지) 문제를 원천 차단.

### 8.3 프리캠 — 오브젝트(카메라) 분리 (`ToggleFreeCam`)

- `FreeLook`(LAlt, 카메라만 짧게 돌려보는 정상 게임플레이 기능)과는 목적이 다른 **디버그 전용 스펙테이터 카메라**다. 헷갈리지 않도록 이름을 `FreeLook`이 아닌 `FreeCam`으로 명확히 구분한다.
- 활성화 시 메인 카메라(또는 별도 디버그 카메라)가 플레이어 캐릭터로부터 완전히 분리되어, 자체 WASD 이동 + QE 상승/하강 + 마우스 시선 회전으로 씬을 자유롭게 비행하며 관찰할 수 있다.
- **결정 사항**: 프리캠 활성 중에도 캐릭터/AI 시뮬레이션은 백그라운드에서 계속 진행(정지하지 않음) — 실제 플레이 중 상황을 외부에서 관찰하며 디버깅하는 용도이기 때문. 완전 정지가 필요하면 별도로 `Time.timeScale`을 조정(8.4 권장 사항 참고).
- 프리캠 활성 중에는 `Player` 맵의 `Move`/`Look` 등 물리 입력이 프리캠 전용 로직으로 라우팅되어야 하므로, 프리캠 On 시 `Player` 맵 콜백 구독을 일시적으로 프리캠 컨트롤러 쪽으로 넘기거나, 별도의 `DebugFreeCam` 서브 액션(같은 물리 키를 재사용하되 Debug 맵 하위에 `FreeCamMove`/`FreeCamLook`을 추가로 정의)을 두는 두 가지 구현 방식 중 하나를 선택 — 구현 단계에서 확정.
- `ToggleFreeCam`을 다시 누르면 카메라가 캐릭터로 즉시 복귀.

### 8.4 추가 권장 디버그 기능 (본 설계 범위 밖, 후속 확장 제안)

- **타임스케일 조절**: `[` / `]` 키로 `Time.timeScale` 감소/증가 (슬로우모션 디버깅).
- **God Mode / 무한 탄약 토글**: `F5` 등에 배치, 밸런스 테스트 시 전투 없이 맵을 돌아볼 때 유용.
- **즉시 텔레포트**: 프리캠으로 이동한 위치로 캐릭터를 순간이동시키는 콘솔 명령 (`ToggleDevConsole`에서 처리, 별도 키 불필요).
- **디버그 HUD**: FPS, 현재 상태 머신 상태, 현재 Action Map 등을 화면에 오버레이 — 토글 키보다는 `ToggleDevConsole` 메뉴 안의 옵션으로 두는 것을 권장(키 소모 최소화).
