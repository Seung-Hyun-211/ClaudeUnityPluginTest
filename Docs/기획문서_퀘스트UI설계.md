# 퀘스트(임무) UI 설계 — 임무를 받기 위한 창

> 플레이어가 NPC로부터 임무(퀘스트)를 받고, 진행 상황을 확인하고, 보상을 수령하는 **UI 화면**을 설계한다.
> NPC/오브젝트 상호작용 자체(감지 범위, `Interact`(F) 판정 등)는 **별도 문서에서 다룬다** — 본 문서는 그 상호작용의 결과로 열리는 퀘스트 관련 창들의 레이아웃/상태/흐름만 다룬다.
> 작성일: 2026-09-17 — [기획문서_대화시네마틱구조설계.md](./기획문서_대화시네마틱구조설계.md)의 `Event` 노드(`OpenQuestOffer`/`OpenQuestTurnIn`)가 본 문서의 화면들을 모달로 연다.

---

## 1. 설계 원칙

1. 퀘스트 관련 창은 두 가지 경로로 열린다: **(A) 대화 중 모달로 열리는 창**(제안/보상수령)과 **(B) 플레이어가 언제든 직접 여는 상시 열람 창**(퀘스트 저널). 두 경로는 여는 방식이 다를 뿐 화면 구성 요소는 최대한 재사용한다.
2. 입력은 새 Action Map 없이 [UI 맵](./기획문서_UI조작설계.md)을 그대로 재사용한다 — `Submit`=확인/수락, `Cancel`=닫기/거절, `Navigate`=목록 탐색, `TabNext`/`TabPrev`=상태별 탭 전환.
3. 본 문서는 **화면 구조**만 다루고, 퀘스트 진행 조건 판정(목표 달성 체크, 저장/로드, 퀘스트 실패 조건 등) 로직은 범위 밖이다 — UI가 무엇을 그릴지 결정하는 데 필요한 최소 데이터 필드만 4장에서 정의한다.

---

## 2. 퀘스트 창 진입 경로

| 경로 | 트리거 | 열리는 화면 |
|---|---|---|
| **A. 대화 중 모달** | 대화 시퀀스의 `Event: OpenQuestOffer(questId)` 노드 도달 | 3.1절 "퀘스트 제안" 화면 |
| **A. 대화 중 모달** | 대화 시퀀스의 `Event: OpenQuestTurnIn(questId)` 노드 도달 | 3.3절 "보상 수령" 화면 |
| **A. 대화 중 모달** | 진행 중인 퀘스트의 NPC를 다시 `Interact`(F)했을 때(대화 그래프가 자동으로 분기) | 3.2절 "진행 중 요약" 화면 |
| **B. 상시 열람** | 플레이어가 직접 여는 단축키/HUD 버튼(키 배정은 후속 문서) | 3.4절 "퀘스트 저널" 화면 |

- 경로 A는 항상 **모달**로 열리며, 열려 있는 동안 대화 시퀀스는 `ModalPending` 상태로 일시정지한다([대화시네마틱구조설계](./기획문서_대화시네마틱구조설계.md) 3장).
- 경로 B는 대화와 무관하게 **독립적으로 여닫을 수 있는 전체 화면 UI**다(다른 일반 메뉴 화면과 동급).

---

## 3. 화면별 설계

### 3.1 퀘스트 제안(Offer) 화면

```
┌─────────────────────────────────────────────┐
│ [NPC 초상화]  NPC 이름                          │
│ ───────────────────────────────────────────  │
│  퀘스트 제목                                    │
│  ───────────────────────────────────────────  │
│  퀘스트 설명 텍스트 (2~4줄 요약)                  │
│                                               │
│  목표                                          │
│   ・ 목표 1                                    │
│   ・ 목표 2                                    │
│                                               │
│  보상                                          │
│   [아이콘] 아이템 x1   [아이콘] 골드 x100          │
│                                               │
│           [ 수락 ]        [ 거절 ]              │
└─────────────────────────────────────────────┘
```

- `Submit` = 수락 버튼(기본 포커스), `Cancel` = 거절과 동일 동작(둘 다 동일 결과로 취급해 사용자가 어느 쪽을 눌러도 자연스럽게 닫히게 함).
- 수락/거절 결과는 [대화시네마틱구조설계](./기획문서_대화시네마틱구조설계.md)의 `nextNodeIfAccepted`/`nextNodeIfDeclined`로 전달되어, NPC가 그에 맞는 대사를 이어서 말하도록 연결된다(예: 수락 시 "고맙네" 대사로 분기).

### 3.2 진행 중 요약 화면

```
┌─────────────────────────────────────────────┐
│ [NPC 초상화]  NPC 이름                          │
│ ───────────────────────────────────────────  │
│  퀘스트 제목 (진행 중)                           │
│  ───────────────────────────────────────────  │
│  목표 진행도                                    │
│   ☑ 목표 1 (완료)                              │
│   ☐ 목표 2  (2 / 5)                           │
│                                               │
│              [ 확인 ]     [ 포기하기 ]           │
└─────────────────────────────────────────────┘
```

- 아직 모든 목표를 달성하지 못했을 때 진행 중인 퀘스트의 NPC를 다시 상호작용하면 뜨는 화면. `Submit` = 확인(닫기), `Cancel` = 확인(닫기)와 동일 — "포기하기" 버튼은 명시적으로 `Navigate`+`Submit`으로만 선택되게 해 실수로 포기되지 않도록 한다(우발적 취소 키로는 발동 불가).
- **결정 사항**: "포기하기"는 파괴적 행동이므로 버튼 선택 후 재확인 팝업(예/아니오)을 한 번 더 띄운다.

### 3.3 보상 수령(Turn-in) 화면

```
┌─────────────────────────────────────────────┐
│ [NPC 초상화]  NPC 이름                          │
│ ───────────────────────────────────────────  │
│  퀘스트 제목 (완료 가능)                          │
│  ───────────────────────────────────────────  │
│  모든 목표 달성!                                 │
│                                               │
│  보상                                          │
│   [아이콘] 아이템 x1   [아이콘] 골드 x100          │
│                                               │
│                  [ 완료 ]                      │
└─────────────────────────────────────────────┘
```

- `Submit` = 완료(보상 지급) 단일 버튼. 거절/취소 개념이 없음(모든 목표를 달성한 보상은 항상 받는 구조로 단순화).
- 완료 시 보상 지급 연출(아이콘이 인벤토리 방향으로 튀는 등)은 8장 후속 범위.

### 3.4 퀘스트 저널(전체 목록)

```
┌─────────────────────────────────────────────┐
│  [진행중] [완료] [실패]      ← TabNext/TabPrev  │
│ ───────────────────────────────────────────  │
│  ▸ 퀘스트 A (진행 중)                           │
│  ▸ 퀘스트 B (진행 중)                           │
│  ▸ 퀘스트 C (진행 중)                           │
│ ───────────────────────────────────────────  │
│  [선택한 퀘스트 상세 패널]                        │
│   목표 목록 / 보상 / 현재 위치(맵 아이콘, 후속)     │
└─────────────────────────────────────────────┘
```

- `TabNext`/`TabPrev`(Q/E, [UI조작설계](./기획문서_UI조작설계.md) 2장)로 진행중/완료/실패 탭 전환, `Navigate`로 목록 스크롤, `Submit`으로 상세 패널 표시.
- 대화와 무관하게 열리므로 재생 상태 머신에 영향 없음 — 일반 메뉴 화면과 동일하게 `Player` 맵을 끄고 `UI` 맵만 활성화.

## 4. 데이터 (UI 표시용 최소 필드)

```
QuestUIData
├─ questId
├─ title
├─ description
├─ giverNpcName / giverNpcPortrait
├─ objectives: [{ text, isCompleted, currentCount, requiredCount }]
├─ rewards: [{ icon, name, amount }]
└─ state: enum { Offered, InProgress, ReadyToTurnIn, Completed, Failed }
```

- `state`에 따라 3.1~3.4절 중 어떤 화면을 보여줄지 결정한다(퀘스트 진행 로직 자체는 이 데이터를 채워주는 별도 시스템의 책임이며 본 문서 범위 밖).

---

## 5. 결정 사항 요약

- 퀘스트 창은 **대화 중 모달로 열리는 제안/진행중요약/보상수령 3화면**과 **플레이어가 직접 여는 퀘스트 저널**로 구분.
- 제안 화면은 `Submit`=수락, `Cancel`=거절이지만 둘 다 창을 닫는 동일한 흐름으로 취급하고, 결과만 대화 시퀀스의 분기로 전달.
- 진행 중 요약 화면의 "포기하기"는 `Navigate`+`Submit`으로만 선택 가능하게 해 우발적 취소를 방지하고, 선택 후 재확인 팝업을 한 번 더 띄움.
- 보상 수령 화면은 거절 개념 없이 `Submit` 단일 버튼으로 단순화.
- 퀘스트 저널은 `TabNext`/`TabPrev`(진행중/완료/실패)로 탭 전환, 새 Action Map 없이 `UI` 맵 재사용.

---

## 6. 추가 권장 사항

- **퀘스트 알림 토스트**: 위 모달들과 별개로, 새 퀘스트 수락됨/목표 갱신됨/완료 가능해짐을 화면 우측 상단에 짧게 띄우는 상시 HUD 요소를 권장 — 모달을 열지 않고도 진행 상황을 인지시킴.
- **월드 스페이스 마커**: 퀘스트 저널에서 특정 퀘스트를 "추적(Track)" 설정하면 월드/미니맵에 목표 위치 아이콘을 표시하는 기능을 권장(별도 문서에서 구체화).
- **다중 퀘스트 동시 제안 방지**: 한 NPC가 동시에 여러 퀘스트를 제안하지 않도록, 한 번에 하나의 `OpenQuestOffer` 모달만 큐에 쌓이지 않고 순차 처리되도록 권장(이미 3장에서 모달 단일 처리로 설계되어 자연히 만족됨).
- **보상 미리보기 강조**: 제안 화면의 보상 아이템에 마우스 호버/포커스 시 상세 툴팁(아이템 설명)을 띄우는 것을 권장 — [UI조작설계](./기획문서_UI조작설계.md) 7장의 툴팁 규칙 재사용.

---

## 7. 후속 설계 범위

- NPC/오브젝트 상호작용 트리거 시스템(감지 범위, `Interact`(F) 판정, 상호작용 가능 오브젝트 종류) — 별도 문서.
- 퀘스트 진행 조건 판정 로직(목표 달성 체크, 저장/로드, 실패 조건).
- 퀘스트 저널을 여는 단축키/HUD 버튼 배정.
- 월드/미니맵 퀘스트 마커 UI.
- 보상 지급 연출(인벤토리 슬롯으로 아이콘이 이동하는 등).
