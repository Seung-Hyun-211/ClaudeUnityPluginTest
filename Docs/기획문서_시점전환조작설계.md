# 시점 전환(ViewSwitch) 조작 설계 (Input Action 기반)

> [기획문서_시점전환슈팅게임.md](./기획문서_시점전환슈팅게임.md) 2.1절(시점 전환 시스템)에서 정의한 1인칭↔3인칭 전환 메커닉을, [기획문서_캐릭터조작설계.md](./기획문서_캐릭터조작설계.md) / [기획문서_무기전투조작설계.md](./기획문서_무기전투조작설계.md)의 `Player` Action Map 입력 체계에 통합하는 문서.
> 작성일: 2026-09-17

## 1. 키 재검토 및 결정

기획 문서 2.1절 초안에는 전환 키가 "기본 `V` (리바인딩 가능)"로 적혀 있었으나, 이후 무기/전투 조작 설계에서 `V`를 **근접 공격(Melee)** 키로 확정했기 때문에 충돌한다.

- **결정 사항**: 시점 전환 키를 `V`에서 **마우스 가운데 버튼(MMB, 휠 클릭)** 으로 변경한다.
  - 이유 1: `LMB`(발사) / `RMB`(조준) 옆에 위치한 `MMB`를 "카메라·시점 관련 입력" 묶음으로 함께 두면 조작 체계가 직관적이다(발사·조준·시점이 모두 마우스 버튼 3개에 모임).
  - 이유 2: 키보드 쪽은 이미 이동(WASD)·자세(C/Shift/Q/E)·상호작용(F)·전투 보조(B/R/V/G/1~4)로 빽빽하게 채워져 있어, 손가락 이동 부담이 적은 MMB가 더 접근성이 좋다.
  - 리바인딩 가능하도록 Input Actions 에셋에는 사용자 설정에서 재매핑 가능한 일반 바인딩으로 등록한다(고정 하드코딩 금지).

---

## 2. 액션 정의

| 액션명 | 타입 | 바인딩 | 방식 | 설명 |
|---|---|---|---|---|
| `ViewSwitch` | Button | Mouse Middle Button(MMB) | Press(트리거 시 1회) → 토글 | 1인칭 ↔ 3인칭 시점 전환 |

`Player` Action Map 소속이며, 캐릭터 조작(이동/시점)·무기/전투 조작과 마찬가지로 게임플레이 중에만 활성화된다.

---

## 3. 전환 동작 규칙

### 3.1 기본 토글 + 전환 쿨다운 (이전 문서의 미결 사항 확정)

기획 문서 2.1절에서 "전환 스팸 방지" 옵션 A(재정렬 딜레이)/B(이동 페널티) 중 하나를 밸런스 테스트로 결정하기로 남겨두었다. 본 문서에서 아래와 같이 확정한다.

- **결정 사항**: 전환 직후 **약 0.25초의 입력 쿨다운**을 둔다. 이 시간은 3.3절(카메라 연출)의 블렌드 시간과 동일하게 맞춰, "카메라가 실제로 다 전환되기 전까지는 재전환 입력을 받지 않는다"는 원칙으로 통일한다.
  - 쿨다운 중 들어온 `ViewSwitch` 입력은 무시(큐잉하지 않고 드롭) — 연타해도 전환이 밀리거나 쌓이지 않게 한다.
  - 이동/사격/조준 등 다른 입력은 전환 쿨다운과 무관하게 항상 정상 처리된다. 시점만 잠깐 전환 애니메이션 중일 뿐, 캐릭터 행동은 멈추지 않는다.
  - 이동 속도 패널티(옵션 B)는 채택하지 않는다 — 전환 자체에 이동 패널티까지 주면 슈팅 전투 중 전환을 꺼리게 되어 "상황에 맞는 시점 선택"이라는 핵심 재미를 해치기 때문.

### 3.2 강제 시점 상태와의 상호작용

기획 문서 2.1절에서 정의한 강제 시점 규칙을 `ViewSwitch` 입력 처리에 반영한다.

| 강제 시점 상황 | 출처 | `ViewSwitch` 입력 처리 |
|---|---|---|
| 스코프/조준경 사용 중 (`Aiming` 상태, `forcesFirstPersonOnADS = true`인 무기) | [무기전투조작설계](./기획문서_무기전투조작설계.md) 4장 | **입력 무시**. 강제 1인칭 상태에서는 수동 전환 불가 — 조준을 풀어야(`AimToggle` 재탭) 다시 자유롭게 전환 가능 |
| 등반/구르기/슬라이딩 모션 중 | 캐릭터 이동 확장(후속) | **입력 무시**, 강제 3인칭 유지 |
| 사망/리스폰 연출 중 | 게임플레이 흐름 | **입력 무시**, 강제 3인칭 유지 |
| 위 조건이 전부 해제된 시점 | — | 다시 자유 토글 가능. 강제 조건이 걸리는 순간 `ViewSwitch`가 눌려 있었더라도 큐잉하지 않음(해제 직후 자동 전환 없음, 사용자가 다시 눌러야 함) |

- 강제 시점 조건이 걸린 상태에서 `ViewSwitch`를 누르면, 입력을 무시함과 동시에 짧은 UI 피드백(예: 조준선 근처 아이콘을 붉게 1회 깜빡임 + 거부 사운드)을 주어 "왜 안 바뀌는지" 사용자가 즉시 인지하게 한다 — 기획 문서 6장 UI/UX의 "전환 가능 여부 피드백" 규칙과 연동.

### 3.3 `FreeLook`과의 상호작용

- `FreeLook`(Left Alt, [캐릭터조작설계](./기획문서_캐릭터조작설계.md) 4.2절)이 진행 중일 때 `ViewSwitch`가 입력되면: **`FreeLook`을 즉시 취소**(카메라 Yaw 오프셋을 0으로 리셋)한 뒤 시점 전환을 수행한다.
  - 이유: FreeLook의 카메라 오프셋은 "현재 시점(1인칭 또는 3인칭)의 카메라 리그" 기준으로 계산되어 있어, 시점 자체가 바뀌면 오프셋 값이 의미를 잃는다. 전환 시 함께 리셋하는 것이 가장 예측 가능한 동작이다.
- 반대로 `ViewSwitch` 쿨다운(3.1절) 중에는 `FreeLook` 진입 자체는 막지 않는다(카메라 관찰 기능이라 전환 쿨다운과 독립적으로 둬도 문제 없음).

### 3.4 `Shoulder`(견착)와의 상호작용

- `Shoulder`(RMB 홀드, [무기전투조작설계](./기획문서_무기전투조작설계.md) 4장) 상태는 강제 시점을 걸지 않으므로, 이 상태에서 `ViewSwitch` 입력은 정상적으로 동작한다.
- 다만 시점이 바뀌는 순간에도 `Shoulder` 자세 자체는 유지된다(1인칭에서 견착 중 3인칭으로 바꿔도 여전히 견착 중인 채로 3인칭 오버숄더 조준 자세로 표시).

### 3.5 카메라 전환 연출 (기존 3.3절 내용과의 연결)

- 실제 카메라 블렌드는 메인 기획 문서 3.3절에서 정의한 대로 Cinemachine 가상 카메라의 `Priority` 스왑 + 짧은 블렌드(0.15~0.25초)를 사용한다. 본 문서의 3.1절 쿨다운 값(0.25초)은 이 블렌드 시간의 상한과 맞춘 것이다.
- 블렌드 지속시간과 `ViewSwitch` 쿨다운 값은 반드시 하나의 상수로 공유 관리한다(예: `ViewSwitchConfig.blendDuration`). 두 값이 따로 놀면 "카메라는 다 안 바뀌었는데 입력은 풀렸다" 같은 불일치가 생긴다.

## 4. 처리 순서 (의사코드)

```csharp
void OnViewSwitch()
{
    if (isViewSwitchOnCooldown) return;                 // 3.1 쿨다운 중 무시
    if (IsViewForced(out var reason))                    // 3.2 강제 시점 조건
    {
        PlayViewSwitchDeniedFeedback(reason);
        return;
    }

    if (isFreeLookHeld) CancelFreeLook();                // 3.3 FreeLook 취소 후 전환

    currentView = (currentView == ViewMode.FirstPerson)
        ? ViewMode.ThirdPerson
        : ViewMode.FirstPerson;

    BlendCameraTo(currentView, duration: ViewSwitchConfig.blendDuration);
    StartViewSwitchCooldown(ViewSwitchConfig.blendDuration); // 3.1/3.5: 블렌드 시간과 동일하게
}

bool IsViewForced(out ForcedViewReason reason)
{
    if (weapon.forcesFirstPersonOnADS && playerState.isAiming) { reason = ForcedViewReason.ScopeADS; return true; }
    if (playerState.isClimbingOrRollingOrSliding)            { reason = ForcedViewReason.TraversalMotion; return true; }
    if (playerState.isDeadOrRespawning)                      { reason = ForcedViewReason.DeathCutscene; return true; }
    reason = ForcedViewReason.None;
    return false;
}
```

## 5. Input Actions 에셋 반영

```
Action Map: Player (기존 항목에 추가)
├─ ... (Move / Look / FreeLook / Jump / Crouch / Sprint / Lean / Interact / Fire / AimToggle / Shoulder /
│      FireModeSwitch / AimZoomAdjust / Reload / WeaponSlot1~4 / WeaponCycle / Melee / ThrowLethal)
└─ ViewSwitch   <Button>   [Mouse/middleButton]
```

- 물리 키 충돌 재확인: `MMB`는 `LMB`(Fire)/`RMB`(AimToggle·Shoulder)와 서로 다른 컨트롤이라 겹치지 않고, 키보드 쪽 어떤 액션과도 겹치지 않는다. 문제 없음.

## 6. 결정 사항 요약

- **전환 키**: `V` → **마우스 가운데 버튼(MMB)** 으로 변경 확정 (기존 무기전투조작설계의 `Melee(V)`와의 충돌 해소).
- **전환 방식**: Press 즉시 토글 + **0.25초 입력 쿨다운**(옵션 A 계열 채택, 이동 속도 페널티인 옵션 B는 미채택). 쿨다운 값은 카메라 블렌드 시간과 동일하게 공유 관리.
- **강제 시점 중 입력**: 스코프 ADS / 등반·구르기·슬라이딩 / 사망·리스폰 연출 중에는 `ViewSwitch` 입력을 무시하고 거부 피드백(아이콘 깜빡임+사운드)을 준다.
- **`FreeLook`과의 관계**: 전환 시 `FreeLook`을 즉시 취소(오프셋 리셋) 후 시점을 바꾼다.
- **`Shoulder`와의 관계**: 견착 상태는 시점 전환을 막지 않으며, 전환 후에도 견착 자세는 유지된다.

## 7. 추가 권장 사항

- **시점별 카메라 설정 분리 저장**: 감도(Sensitivity), FOV 등은 1인칭/3인칭 각각 독립적으로 기억해 두는 것을 권장(전환 시 "이전에 그 시점에서 쓰던 설정"으로 즉시 복귀).
- **전환 중 입력 버퍼링(향후 검토)**: 지금은 쿨다운 중 입력을 드롭하지만, 플레이테스트에서 "전환이 씹혔다"는 불만이 나오면 쿨다운 종료 직후 자동 전환되도록 짧은 입력 버퍼(예: 0.1초)를 추가하는 방안을 검토할 것.
- **게임패드 바인딩**: 버튼이 부족한 패드에서는 `MMB` 대신 `클릭형 스틱(L3/R3)` 또는 `D-Pad` 한 방향에 배정하는 것을 권장 — 무기전투조작설계 6.6절의 게임패드 확장 계획과 함께 정리할 것.
- **UI 인디케이터 연동**: 메인 기획 문서 6장에서 정의한 "시점 전환 인디케이터"가 `ViewSwitch` 처리 결과(성공/거부)를 그대로 구독하도록 이벤트를 하나로 통일(성공 시 아이콘 전환 애니메이션, 거부 시 흔들림 애니메이션).
