# 시점 전환 슈팅 게임 기획 문서

> 1인칭(FPS)과 3인칭(TPS) 시점을 실시간으로 전환할 수 있는 슈팅 게임 기획서
> 작성일: 2026-09-17

---

## 1. 개요

### 1.1 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 게임명(가칭) | Shift Point (가칭) |
| 장르 | 시점 전환 슈팅 (FPS/TPS 하이브리드) |
| 플랫폼 | PC (Unity 6, URP), 추후 콘솔 이식 고려 |
| 인원 구성 | 1인 ~ 소규모 팀 기준 (본 문서는 프로토타입 범위 기준으로 작성) |
| 타겟 세션 | 1회 플레이 10~20분 내외 (스테이지/매치 기준) |
| 핵심 타겟층 | FPS/TPS 슈팅 장르 팬, 시점 전환 기믹에 흥미가 있는 유저 |

### 1.2 한 줄 컨셉

**"버튼 하나로 전투 시야를 바꾼다"** — 정밀 사격이 필요한 순간엔 1인칭으로, 주변 상황 파악과 엄폐/기동이 필요한 순간엔 3인칭으로, 플레이어가 스스로 유리한 시점을 선택하며 싸우는 슈팅 게임.

### 1.3 기획 의도

- 기존 FPS/TPS는 장르가 고정되어 있어 시점에 따른 장단점이 게임 설계에 이미 녹아 있음.
- 시점 전환을 코어 메커닉으로 승격시켜, "어떤 시점을 언제 쓰는가"가 곧 전략적 선택이 되도록 설계.
- 1인칭 = 정밀도·몰입감 / 3인칭 = 공간 지각·기동성이라는 트레이드오프를 명확히 하여 장르적 재미를 이중으로 제공.

## 2. 핵심 게임플레이

### 2.1 시점 전환 시스템 (핵심 메커닉)

| 구분 | 1인칭 시점 (FPS) | 3인칭 시점 (TPS) |
|---|---|---|
| 전환 키 | 기본 `V` (리바인딩 가능) | 동일 키 토글 |
| 조준 정확도 | 높음 (반동/탄퍼짐 페널티 감소) | 보통 (기본 반동/탄퍼짐) |
| 시야 범위(FOV) | 좁음 (60~75°), 몰입감 위주 | 넓음 (75~90°), 주변 인지 위주 |
| 이동 속도 | 소폭 감소 (정밀 사격 자세) | 기본 이동 속도 |
| 엄폐/코너 확인 | 불가 (직접 노출 필요) | 가능 (캐릭터 뒤에서 코너 일부 확인) |
| 피격 판정 부위 확인 | 조준선 중심 | 캐릭터 전신 실루엣으로 위협 인지 용이 |
| 추천 상황 | 원거리 교전, 저격, 정밀 헤드샷 | 근접전, 엄폐물 활용, 추격/후퇴, 플랫포밍 |

**전환 규칙**
1. 전환은 **즉시 토글**이며 쿨다운 없음 (초기안). 단, 밸런스 테스트 결과에 따라 아래 중 하나를 적용 검토:
   - 옵션 A: 전환 후 0.2~0.3초 조준 흔들림(재정렬 딜레이) 부여 → 시점 스와핑 스팸 방지.
   - 옵션 B: 전환 자체는 무제한이나, 전환 직후 잠깐 이동 속도 페널티.
2. 특정 상태에서는 시점 고정:
   - 스코프/조준경 사용 중 → 강제 1인칭.
   - 등반/구르기/슬라이딩 모션 중 → 강제 3인칭 (모션 가독성 확보).
   - 사망/리스폰 연출 중 → 3인칭 고정.
3. 무기별로 "권장 시점"은 있으나 강제하지 않음 (플레이 스타일 존중). 단, 저격 소총 등 일부 무기는 조준(ADS) 시 무조건 1인칭 스코프 뷰로 전환.

### 2.2 전투 시스템

- **무기 슬롯**: 주무기(소총/저격/샷건 중 택1), 보조무기(권총), 근접무기(칼), 투척물(수류탄류) — 4슬롯 기본.
- **조준(ADS)**: 우클릭 홀드. 1인칭에서는 정밀 조준, 3인칭에서는 오버숄더 조준(카메라가 어깨너머로 당겨짐).
- **반동/탄퍼짐**: 시점별 차등 적용 (2.1 표 참고). 동일 무기라도 시점에 따라 체감 난이도가 달라지도록 설계.
- **엄폐 시스템**: 3인칭에서만 벽에 캐릭터를 밀착시켜 부분 노출 사격 가능 (1인칭에서는 엄폐 브레이크 시 자동으로 전신 노출).
- **체력/실드**: 체력 + 재생형 실드 구조 (실드는 비전투 시 자동 회복, 체력은 회복 아이템/스킬 필요) — 표준 슈팅 장르 관례를 따르되 세부 수치는 밸런싱 단계에서 확정.

### 2.3 이동 시스템

- 기본 이동, 스프린트, 슬라이딩, 구르기(회피기), 낮은 엄폐물 앉기.
- 고급 이동(벽타기, 그래플링 등)은 확장 콘텐츠로 백로그에 배치 (MVP 범위 제외).
- 이동 중 시점 전환은 자유롭게 허용하되, 위 2.1의 강제 시점 규칙을 따름.

## 3. 카메라 설계

### 3.1 1인칭 카메라

- 무기 뷰모델 + 손 애니메이션 필요.
- 카메라 흔들림(걷기/뛰기 시 헤드밥)은 옵션으로 On/Off 제공 (멀미 방지).
- FOV 슬라이더 제공 (60~100°, 유저 설정 가능).

### 3.2 3인칭 카메라

- 오버숄더 방식 (캐릭터 기준 우측 뒤 오프셋), 벽/장애물 충돌 시 카메라 자동 줌인(클리핑 방지).
- 좌/우 숄더 스위칭 지원 검토 (코너 반대편 확인용, Q 키 등).
- 조준 시 FOV 축소 + 카메라가 캐릭터 쪽으로 밀착.

### 3.3 시점 전환 연출

- 전환 시 단순 컷이 아닌 짧은(0.15~0.25초) 카메라 블렌딩/줌 연출로 시점 전환의 방향감을 유지 (Unity Cinemachine의 Blend 기능 활용 권장).
- 전환 시 캐릭터 모델은 항상 존재(1인칭에서도 하반신/그림자 렌더링)하여 시점 전환 시 위화감 최소화.

## 4. 기술 설계 (Unity 구현 관점)

### 4.1 권장 구조

- **Cinemachine (또는 유사 카메라 스택)**: FPS/TPS용 가상 카메라 2개를 두고, 시점 전환 시 `Priority` 값을 스왑하여 블렌드 전환.
- **입력 시스템**: Unity Input System 사용 (본 프로젝트에 이미 Input Actions 구성 존재), 시점 전환을 별도 Action으로 바인딩.
- **캐릭터 모델**: 1인칭 전용 암즈(Arms) 리그와 풀바디(Full-body) 리그를 분리하거나, 단일 풀바디 리그에 1인칭 시 머리 메시만 컬링하는 방식 검토.
- **탄퍼짐/반동 파라미터화**: 무기 데이터(ScriptableObject)에 `fpAccuracyMultiplier`, `tpAccuracyMultiplier` 등 시점별 계수를 별도 필드로 관리하여 밸런싱 용이하게 설계.
- **상태 머신**: 플레이어 상태(이동/조준/엄폐/구르기 등)와 카메라 모드(1인칭/3인칭)를 분리된 상태 머신으로 관리하고, 특정 상태 진입 시 강제 시점 오버라이드를 적용하는 구조 권장.

### 4.2 데이터 구조 예시 (개념 수준)

```
WeaponData (ScriptableObject)
├─ damage
├─ fireRate
├─ recoil
├─ fpAccuracyMultiplier   // 1인칭 정확도 보정
├─ tpAccuracyMultiplier   // 3인칭 정확도 보정
├─ forcesFirstPersonOnADS // 조준 시 1인칭 강제 여부 (저격 소총 등)
└─ viewModelPrefab / worldModelPrefab
```

### 4.3 성능/최적화 고려사항

- 두 카메라(1인칭/3인칭)를 항상 활성 상태로 둘 경우 렌더링 비용 증가 → 비활성 카메라의 불필요한 렌더 패스는 최소화.
- 1인칭 전용 뷰모델은 별도 레이어로 분리하여 3인칭 카메라에는 렌더링되지 않도록 처리(Culling Mask).

## 5. 콘텐츠 구성 (MVP 기준)

### 5.1 MVP 범위

- 플레이어 캐릭터 1종 (이동/전투/시점전환 모두 지원)
- 무기 3종: 돌격소총(범용), 저격소총(1인칭 스코프 강제), 샷건(근접 특화, 3인칭 권장)
- 테스트 맵 1개: 근거리 교전 구역 + 중장거리 개활지 + 엄폐물 배치 구역을 모두 포함한 소규모 맵
- 적 AI: 기본 사격형 적 1종 (플레이어 시점 전환 대응은 MVP 제외, 추후 고급 AI 반응 로직 확장)
- 게임 모드: 웨이브 클리어 형 싱글 플레이 (멀티플레이는 확장 로드맵)

### 5.2 확장 로드맵 (MVP 이후)

1. 무기/공격 유형 추가 (유탄, 화염 등)
2. 적 AI 고도화 — 플레이어 시점에 따라 다른 대응 전략(예: 3인칭일 때 측면 우회, 1인칭일 때 은엄폐물 활용)
3. PvP 모드 (시점 전환을 활용한 대인전 밸런스 별도 검증 필요)
4. 이동 시스템 확장 (그래플링, 벽타기 등)
5. 콘솔 컨트롤러 지원 (시점 전환 버튼 매핑 별도 설계 필요)

## 6. UI/UX

- **시점 전환 인디케이터**: 화면 하단 또는 조준선 근처에 현재 시점(1인칭/3인칭) 아이콘 표시.
- **전환 가능 여부 피드백**: 강제 시점 상태(스코프 사용 중 등)에서는 전환 키 입력 시 짧은 UI 진동/음성 피드백으로 "전환 불가"를 명확히 안내.
- **접근성 옵션**: 헤드밥 On/Off, FOV 슬라이더, 카메라 감도(시점별 개별 설정), 색맹 모드 등 기본 접근성 옵션 제공.
- **튜토리얼**: 게임 시작 시 시점 전환의 장단점을 실전 상황(저격 vs 근접전)으로 직접 체험시키는 짧은 튜토리얼 스테이지 구성.

## 7. 밸런싱 방향

- 1인칭과 3인칭 중 어느 한쪽이 "항상 우위"가 되지 않도록, 거리/상황별 유불리를 명확히 분리:
  - 원거리·정지 교전 → 1인칭 우위
  - 근거리·기동 교전, 엄폐 활용 → 3인칭 우위
- 실제 수치(정확도 계수, FOV, 이동속도 페널티 등)는 프로토타입 제작 후 플레이테스트를 통해 반복 조정.
- 전환 스팸(초당 다수 전환)으로 두 시점의 장점만 취하는 편법을 방지하기 위한 안전장치(딜레이/페널티)를 프로토타입 단계에서 반드시 검증.

## 8. 리스크 및 검토 필요 사항

| 리스크 | 내용 | 대응 방향 |
|---|---|---|
| 시점 전환 스팸 악용 | 전환을 남발해 두 시점의 장점만 취하는 플레이 | 전환 쿨다운/딜레이 옵션 A·B 중 플레이테스트로 확정 |
| 개발 리소스 2배 부담 | 1인칭 뷰모델 + 3인칭 풀바디 모델을 모두 제작/애니메이션 필요 | 단일 풀바디 리그 + 1인칭 시 헤드 컬링 방식으로 리소스 절감 검토 |
| 멀미(모션 시크니스) | 잦은 시점 전환 및 카메라 블렌딩으로 인한 어지러움 | 블렌딩 시간/방식 옵션화, 헤드밥 Off 옵션 기본 제공 |
| 밸런스 붕괴 | 특정 시점이 명백히 우위가 되는 경우 장르 정체성 훼손 | 정기적 플레이테스트 및 시점별 승률/픽률 데이터 수집 체계 필요 |
