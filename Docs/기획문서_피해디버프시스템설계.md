# 피해 & 디버프 시스템 설계 (게임플레이 로직)

> [기획문서_디버프스크린셰이더설계.md](./기획문서_디버프스크린셰이더설계.md)에서 "디버프 게임플레이 로직 본체(피해량, 지속시간, 스택 규칙)는 별도 문서"로 미뤄두었던 부분을 채우는 문서다.
> **직접 피해형**(출혈, 독 — 체력을 직접 깎음)과 **생리 상태형**(뇌진탕, 탈수, 탈진 — 신체 컨디션 저하로 전투력을 깎음) 두 축으로 디버프를 설계한다.
> 실제 셰이더/UI 구현은 각각 [디버프스크린셰이더설계](./기획문서_디버프스크린셰이더설계.md), 향후 HUD 문서를 참고하고, 본 문서는 **수치 모델과 발생·해제 규칙**에 집중한다.
> 작성일: 2026-09-17

---

## 1. 설계 원칙

1. **두 축으로 분류한다.** "체력을 직접 깎는가(직접 피해형)" vs "신체 컨디션을 깎아 전투력을 떨어뜨리는가(생리 상태형)" — 이 분류는 [디버프스크린셰이더설계](./기획문서_디버프스크린셰이더설계.md)의 `effectCategory`(`DamageFeedback`/`Perceptual`) 분류와 정확히 대응한다: 직접 피해형=`DamageFeedback`(화면 중앙을 가리지 않음), 생리 상태형=`Perceptual`(중앙 포함, 실제 지각이 저하된 느낌).
2. **생리 상태형 디버프는 조작 권한을 빼앗지 않는다.** 뇌진탕이 걸렸다고 시점 전환이 막히거나, 탈진했다고 이동 자체가 불가능해지는 식으로 설계하지 않는다 — 항상 "할 수는 있지만 불리해지는" 수치 페널티로만 표현한다(플레이어 주도성 보존).
3. **실드는 생물학적 이상 상태의 영향을 받지 않는다.** [메인 기획서](./기획문서_시점전환슈팅게임.md) 2.2절의 실드는 에너지 배리어 개념이므로, 출혈/독 같은 DoT(지속 피해)는 실드를 무시하고 **체력을 직접** 깎는다 — 실드가 있어도 출혈은 그대로 진행된다는 뜻이며, 이를 통해 실드만으로는 완전한 안전을 보장하지 않는 긴장감을 준다.
4. **치료 수단은 새 시스템을 만들지 않는다.** 지혈 붕대, 해독제, 물통 등은 [상점시스템설계](./기획문서_상점시스템설계.md)의 구매 탭에 일반 아이템으로 등록하고, 사용은 인벤토리(후속 문서)의 소비 아이템 사용 흐름을 그대로 탄다.

---

## 2. 디버프 분류 체계

| 분류 | 정의 | 해당 디버프 | 화면 이펙트 카테고리 |
|---|---|---|---|
| **직접 피해형(Direct Damage)** | 시간에 따라 체력을 직접 깎는 DoT | 출혈(Bleeding), 독(Poison) | `DamageFeedback`(화면 중앙 비움) |
| **생리 상태형(Physiological)** | 체력을 직접 깎지 않고, 신체 컨디션 저하로 전투 능력치(정확도, 이동속도, 회복력 등)를 깎음 | 뇌진탕(Concussion), 탈수(Dehydration), 탈진(Exhaustion) | `Perceptual`(화면 중앙 포함) |

---

## 3. 공통 데이터 구조

```
DebuffDefinition (ScriptableObject, 디버프 종류당 1개)
├─ debuffId
├─ category: enum { DirectDamage, Physiological }
├─ screenEffectProfile: DebuffScreenEffectProfile 참조  // 화면 표현은 그 문서에 위임
├─ maxSeverity / maxStacks                              // 디버프별로 스택 or 중증도 레벨 중 하나만 사용
├─ stackBehavior: enum { IndependentStacks, RefreshOnly, SeverityLevel, GaugeBased }
├─ tickInterval                                          // DoT 틱 주기 (직접 피해형)
└─ cureConditions: CureCondition[]                       // 6장

DebuffInstance (런타임)
├─ definition
├─ remainingDuration / currentStacks / currentSeverity / currentGauge  // stackBehavior에 따라 다른 필드 사용
└─ appliedAtTime
```

- **결정 사항**: 다섯 디버프를 하나의 획일적인 "스택 카운트" 모델로 억지로 통일하지 않는다. 출혈처럼 "몇 번 베였나"가 중요한 디버프는 스택형, 뇌진탕처럼 "얼마나 심한가"가 중요한 디버프는 중증도 레벨형, 탈수/탈진처럼 "자원이 얼마나 남았나"가 중요한 디버프는 게이지형으로 — `stackBehavior` 필드로 모델만 다르게 선택하고 나머지 파이프라인(화면 이펙트 연동, 치료 조건 처리)은 공통으로 재사용한다.

## 4. 직접 피해형(Direct Damage) 설계

### 4.1 출혈(Bleeding)

| 항목 | 내용 |
|---|---|
| 발생 조건 | 예리한 무기(칼, 파편 계열 탄) 피격 시 일정 확률로 적용, 또는 특정 적의 고유 공격(발톱 공격 등) |
| 모델 | **독립 스택형**(`IndependentStacks`), 최대 5스택 — 스택마다 각자 타이머를 가짐 |
| 틱 데미지 | 스택 1개당 최대 체력의 1%/초, 5스택이면 5%/초로 선형 누적 |
| 지속시간 | 스택당 6초 |
| 해제 | 지혈 붕대(즉시 전체 스택 제거) 또는 시간 경과로 스택이 하나씩 자연 만료 |

- **결정 사항**: 스택을 독립적으로 두는 이유 — "여러 번 베일수록 급격히 위험해진다"는 근접전 특유의 리스크를 표현하되, 붕대 1개로 한 번에 전부 해결되게 해 치료 액션 자체는 번거롭지 않게 한다(스택마다 붕대를 따로 써야 하면 인벤토리 관리 피로도만 커짐).

### 4.2 독(Poison)

| 항목 | 내용 |
|---|---|
| 발생 조건 | 특정 적(독개구리류)의 공격, 가스 트랩, 독성 환경 구역 |
| 모델 | **갱신형**(`RefreshOnly`) — 새로 중독되면 지속시간만 최대치로 갱신되고, 데미지는 더 강한 쪽으로 대체(약한 독이 강한 독을 덮어쓰지 않음) |
| 틱 데미지 | 최대 체력의 2%/초 (고정, 스택 없음) |
| 지속시간 | 8초 |
| 특수 규칙 | **최소 체력 25% 아래로는 독 데미지만으로 죽지 않는다**(소프트 캡) — 출혈과의 차별점 |
| 해제 | 해독제, 또는 시간 경과로 자연 만료 |

- **결정 사항**: 독에 소프트 캡을 두는 이유 — 독은 "천천히 스며드는 위협"이라는 정서를 주는 장치이지, 무방비 상태에서 방치하면 반드시 죽는 확정 사망 장치로 쓰지 않기 위함. 반면 **출혈은 소프트 캡을 두지 않아 방치하면 사망까지 이를 수 있다** — "근접전에서 베인 상처는 즉각적인 생명의 위협"이라는 톤 차이를 수치로 구현한 것.

### 4.3 직접 피해형 공통 규칙

- 두 디버프 모두 **실드를 무시하고 체력을 직접** 깎는다(1.3절).
- 동시에 출혈+독이 걸리면 각자의 틱이 독립적으로 진행되며 합산 피해를 입는다(서로 상쇄하거나 대체하지 않음) — 서로 다른 위협이 누적된다는 것을 명확히 전달.

## 5. 생리 상태형(Physiological) 설계

### 5.1 뇌진탕(Concussion)

| 항목 | 내용 |
|---|---|
| 발생 조건 | 폭발 피해, 둔기/헤드샷성 피격을 일정 수치 이상 받았을 때 |
| 모델 | **중증도 레벨형**(`SeverityLevel`), 1~3단계 |
| 레벨별 효과 | 1단계: 화면 이펙트 약, 조준 흔들림(탄퍼짐) +15% / 2단계: 화면 이펙트 중, 탄퍼짐 +35%, 이동속도 -10% / 3단계: 화면 이펙트 강(디버프스크린셰이더설계 4.2절 수치), 탄퍼짐 +60%, 이동속도 -20% |
| 지속시간 | 레벨별 15/25/40초, 추가 피격 시 레벨 상승 및 지속시간 갱신 |
| 자연 감소 | 시간이 지나면 레벨이 한 단계씩 내려감(3→2→1→해제), 즉시 완전 해제는 아님 |
| 해제 아이템 | 진통제/각성제 — 레벨을 1단계 즉시 낮춤(스택 제거가 아니라 레벨 감소) |

- **연동 지점**: 탄퍼짐 증가는 [크로스헤어탄퍼짐설계](./기획문서_크로스헤어탄퍼짐설계.md) 4.2절의 `GetCurrentSpread` 계산식에 `debuffSpreadMultiplier` 항으로 곱해지도록 연동한다(7장에서 해당 문서 수정 반영).

### 5.2 탈수(Dehydration)

| 항목 | 내용 |
|---|---|
| 발생 조건 | **환경 트리거형** — 사막/고열 구역 등 지정된 존(Zone)에 일정 시간(예: 30초) 이상 체류 시에만 게이지가 쌓인다. 평상시에는 상시로 소모되지 않는다 |
| 모델 | **게이지형**(`GaugeBased`), 0(정상)~100(중증) |
| 효과 | 게이지 50 이상: 체력 재생 속도 -30%, 이동속도 -5% / 게이지 80 이상: 체력 재생 속도 -60%, 이동속도 -15%, 화면 아지랑이(Perceptual) |
| 회복 | 해당 존을 벗어나면 게이지가 서서히 자연 감소, 물통 아이템 사용 시 즉시 대폭 감소 |

- **결정 사항**: 상시 수분 관리를 요구하는 서바이벌형 자원으로 만들지 않고, **특정 환경 구역에서만 의미를 갖는 국소적 메커니즘**으로 범위를 제한한다 — 이 게임은 슈팅 전투가 핵심이지 생존 시뮬레이션이 아니므로, 평상시에도 계속 물을 챙겨야 하는 부담을 주면 코어 루프에서 주의를 뺏는다.

### 5.3 탈진(Exhaustion)

| 항목 | 내용 |
|---|---|
| 발생 조건 | 스태미나(행동 자원) 게이지 완전 소진 |
| 모델 | **게이지형**(`GaugeBased`) — 스태미나 게이지 자체가 0에 도달하면 탈진 디버프가 발동, 스태미나가 일정 수준(예: 30%) 이상 회복되면 자동 해제 |
| 효과 | 스프린트 입력 무시(단, 막는 게 아니라 "스태미나가 없어서 가속이 안 붙는다"는 수치적 결과 — 1.2절 원칙에 따라 입력 자체는 항상 받되 효과가 없음), 이동속도 -10%, 탄퍼짐 +25%, 화면 흐릿함(Perceptual) |
| 회복 | 비전투(최근 5초 이상 `Fire` 미사용) 상태를 유지하면 스태미나가 서서히 회복 |

- **결정 사항(신규 자원 도입)**: 탈진을 만들려면 "스태미나" 게이지가 전제로 필요하다. 현재 [캐릭터조작설계](./기획문서_캐릭터조작설계.md)의 `Sprint`는 무제한 홀드 방식으로 설계돼 있었으므로, 본 문서에서 **스태미나 자원을 신규로 도입**하고 `Sprint`/`Lean`/구르기 등 행동 자원 소모 연동은 후속 조정 과제로 남긴다(8장).

### 5.4 생리 상태형 공통 원칙

- 셋 다 **체력을 직접 깎지 않는다** — 전투력 저하로만 작동하며, 직접 피해형과 겹쳐도 사망 원인이 되지 않는다(단, 정확도/이동속도 저하로 인해 간접적으로 죽기 쉬워지는 것은 의도된 설계).
- 화면 이펙트는 모두 `Perceptual`이므로 [디버프스크린셰이더설계](./기획문서_디버프스크린셰이더설계.md)의 안전 영역(3.1절) 예외 없이 중앙까지 흐림/왜곡이 걸린다 — "실제로 몸 상태가 안 좋아서 잘 안 보인다"는 감각을 의도적으로 전달.

## 6. 치료/해제 아이템

| 아이템 | 대상 디버프 | 효과 |
|---|---|---|
| 지혈 붕대 | 출혈 | 모든 출혈 스택 즉시 제거 |
| 해독제 | 독 | 즉시 해제 |
| 진통제/각성제 | 뇌진탕 | 중증도 1단계 즉시 감소 |
| 물통 | 탈수 | 게이지 대폭 즉시 감소 |
| (해당 없음 — 휴식으로만 회복) | 탈진 | 아이템 없음, 비전투 대기로만 회복(5.3절) |

- 모든 치료 아이템은 [상점시스템설계](./기획문서_상점시스템설계.md) 4장 구매 탭의 `buyCatalog`에 일반 아이템처럼 등록한다 — 새 탭/새 UI 불필요.
- **결정 사항**: 탈진에는 의도적으로 소비 아이템을 두지 않는다 — 스태미나 관리(무리하게 스프린트/회피를 남발하지 않는 것)가 곧 전투 판단의 일부가 되도록, 아이템으로 즉시 해결 가능한 문제로 만들지 않는다.

## 8. 결정 사항 요약

- 디버프를 **직접 피해형(DoT, 실드 무시, `DamageFeedback` 화면 카테고리)** 과 **생리 상태형(전투력 저하, 조작권 유지, `Perceptual` 화면 카테고리)** 두 축으로 분류.
- 다섯 디버프를 하나의 스택 모델로 통일하지 않고 **디버프 성격에 맞는 모델(독립 스택/갱신형/중증도 레벨/게이지)** 을 각각 선택.
- **출혈**: 독립 스택(최대 5), 방치 시 사망 가능, 붕대로 전체 즉시 제거.
- **독**: 갱신형(강한 쪽으로 대체), 최소 체력 25% 소프트 캡으로 확정 사망 방지 — 출혈과 톤을 차별화.
- **뇌진탕**: 중증도 1~3단계, 탄퍼짐/이동속도 페널티, 자연 감소는 서서히(한 단계씩).
- **탈수**: 특정 환경 존에서만 발생하는 국소적 메커니즘으로 범위 제한(상시 서바이벌 자원화 지양).
- **탈진**: 신규 스태미나 자원 도입이 전제, 치료 아이템 없이 휴식으로만 회복 — 관리 자체가 전투 판단의 일부가 되도록 설계.
- 생리 상태형 디버프는 **입력/조작을 절대 차단하지 않고 수치 페널티로만** 표현.

## 9. 추가 권장 사항

- **디버프 인지 실패 방지**: HUD 아이콘(후속 문서)에 각 디버프의 잔여 시간/게이지를 항상 노출해, 화면 이펙트를 낮춘 접근성 설정에서도 상태를 놓치지 않게 할 것(디버프스크린셰이더설계 7장과 일관).
- **뇌진탕 3단계 다단 경고**: 최고 중증도 도달 직전에 짧은 경고 사운드/진동(있다면)을 주는 것을 권장 — 페널티가 급격히 커지는 구간이므로 예측 가능성을 준다.
- **탈수 존 사전 고지**: 레벨 디자인 단계에서 탈수 존 진입 시 화면 가장자리에 경고 아이콘(예: 온도계)을 잠깐 띄워, 게이지가 쌓이기 전에 위험 지역임을 알리는 것을 권장.
- **스태미나 게이지 UI**: 탈진 도입에 따라 체력/실드 게이지 옆에 스태미나 게이지를 상시 HUD 요소로 추가할 것을 권장(후속 HUD 문서에서 레이아웃 확정).
- **디버그 연동**: [캐릭터조작설계](./기획문서_캐릭터조작설계.md) 8장의 개발자 콘솔(F1)에서 임의의 디버프를 임의 강도로 즉시 부여/제거하는 명령을 지원하면 밸런싱이 수월하다.

## 10. 후속 설계 범위

- 스태미나(행동 자원) 시스템 본체 — 소모/회복 곡선, `Sprint` 외 다른 행동과의 연동.
- 독/탈수/탈진의 `DebuffScreenEffectProfile` 신규 제작([디버프스크린셰이더설계](./기획문서_디버프스크린셰이더설계.md) 5장 데이터 구조 참고).
- 디버프 HUD 아이콘/게이지 UI 세부 설계.
- 적 AI가 디버프 상태(예: 출혈 중인 플레이어)를 인지하고 전술을 바꾸는지 여부 — 메인 기획서의 적 AI 확장 로드맵과 연결.
- 레벨 디자인 관점의 탈수 존 배치 가이드라인.
