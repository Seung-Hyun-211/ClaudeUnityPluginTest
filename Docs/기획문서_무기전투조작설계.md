# 무기/전투 조작 설계 (Input Action 기반)

> [기획문서_캐릭터조작설계.md](./기획문서_캐릭터조작설계.md)의 `Player` Action Map에 이어지는 무기/전투 조작 설계 문서.
> 좌클릭(발사) / 우클릭(조준)을 탭·홀드로 세분화하고, 무기 발사 모드 전환, 정조준·견착·가변 배율 조준경 조작을 정의한다.
> 작성일: 2026-09-17

---

## 1. 설계 원칙

1. **무기/전투 액션도 `Player` Action Map 소속**이다. 캐릭터 조작(이동/시점)과 별도 맵으로 분리하지 않는다 — 두 그룹은 항상 동시에 켜지고 동시에 꺼지므로(게임플레이 중에만 유효) 맵을 나눌 실익이 없고, 오히려 `PlayerInput`이 여러 맵을 오갈 필요가 없어 코드가 단순해진다. 대신 코드/문서상으로는 "이동 그룹"과 "전투 그룹"으로 역할을 구분해 관리한다.
2. **탭(Tap) vs 홀드(Hold) 분리**: 같은 물리 버튼(우클릭)이라도 짧게 눌렀다 떼는지, 일정 시간 이상 눌러 유지하는지에 따라 서로 다른 액션이 트리거되도록 Unity Input System의 **Tap / Hold 인터랙션**을 사용한다. 두 인터랙션은 동일 컨트롤에 바인딩된 서로 다른 액션에 걸어 자연스럽게 상호 배타적으로 동작시킨다.
3. **발사 모드(단발/점사/연사)는 입력 바인딩이 아니라 무기 데이터 + 런타임 상태로 처리**한다. `B`는 항상 "현재 무기가 지원하는 다음 발사 모드로 전환"하는 단일 액션일 뿐이고, 실제 발사 로직은 좌클릭(`Fire`) 버튼의 눌림 상태를 코드에서 해석해 무기의 현재 발사 모드에 맞게 처리한다.
4. **조준 상태는 3단계 상태 머신**(Relaxed → Shouldered → Aiming)으로 정의해 우클릭 탭/홀드의 상호작용을 명확히 한다(4장 참고).

## 2. Player 맵 — 무기/전투 액션 정의

| 액션명 | 타입 | 바인딩 | 인터랙션/방식 | 설명 |
|---|---|---|---|---|
| `Fire` | Button | 마우스 왼쪽 버튼(LMB) | Press 상태를 매 프레임 조회(`IsPressed`) | 발사 트리거 입력. 실제 발사 방식은 무기의 현재 FireMode가 결정 (3장) |
| `AimToggle` | Button | 마우스 오른쪽 버튼(RMB) | **Tap** 인터랙션 (release ≤ 0.2초) | 짧게 클릭 시 정조준(ADS) On/Off **토글** |
| `Shoulder` | Button | 마우스 오른쪽 버튼(RMB) | **Hold** 인터랙션 (press ≥ 0.2초, started/performed/canceled) | 일정 시간 이상 누르고 있는 동안 견착 자세 유지, 떼면 해제 |
| `FireModeSwitch` | Button | `B` | Press(트리거 시 1회) | 무기의 다음 발사 모드로 전환(단발 ↔ 점사 ↔ 연사, 무기가 지원하는 모드만 순환) |
| `AimZoomAdjust` | Value / Axis(1D) | 마우스 휠(Scroll Y) | Pass Through, 조준 중일 때만 적용(4.3 참고) | 정조준 상태에서 조준경 배율(줌) 단계 조절 |
| `Reload` | Button | `R` | Press(트리거 시 1회) | 재장전 |
| `WeaponSlot1~4` | Button | `1`,`2`,`3`,`4` | Press(트리거 시 1회) | 무기 슬롯 직접 선택 |
| `WeaponCycle` | Value / Axis(1D) | 마우스 휠(Scroll Y) | Pass Through, **비조준 상태일 때만** 적용(6장 참고) | 무기 슬롯 앞/뒤로 순환 전환 |
| `Melee` | Button | `V` | Press(트리거 시 1회) | 근접 공격 |
| `ThrowLethal` | Button | `G` | Press/Hold(쿡오프 지원 시, 6장 권장사항) | 투척물(수류탄 등) 투척 |

> `AimZoomAdjust`와 `WeaponCycle`은 **동일한 물리 입력(마우스 휠)** 을 공유하되, 현재 조준 상태에 따라 코드에서 어느 쪽으로 해석할지 분기한다(6장 "마우스 휠 컨텍스트 분리" 참고). Input Actions 에셋에는 두 액션을 모두 정의해 두고, 실제로 값을 반영할지는 컨트롤러가 상태를 보고 결정한다.

## 3. 발사 모드 (단발 / 점사 / 연사)

### 3.1 무기 데이터 구조 (개념)

```
WeaponData (ScriptableObject)
├─ supportedFireModes: FireMode[]     // 이 무기가 지원하는 모드 목록 (예: [Semi, Auto] 또는 [Semi, Burst, Auto])
├─ currentFireModeIndex: int          // B키로 순환되는 현재 인덱스 (런타임 상태, 무기별로 저장)
├─ fireRate: float                    // 초당 발사 수 (연사/점사 내부 간격 계산에 사용)
├─ burstCount: int                    // 점사 모드일 때 1회 트리거당 발사 수 (예: 3점사)
└─ burstInterval: float               // 점사 내부 탄 간 간격
```

- `FireModeSwitch`(B)를 누르면 `supportedFireModes` 배열 안에서 **다음 모드로만** 순환한다. 예를 들어 어떤 무기가 단발/연사만 지원한다면 점사 단계는 건너뛴다.
- 무기가 발사 모드를 1개만 지원하면(`supportedFireModes.Length == 1`) `FireModeSwitch` 입력을 받아도 아무 변화가 없으며, HUD에도 전환 불가로 표시(또는 아예 비활성 처리).

### 3.2 `Fire` 버튼 해석 로직 (모드별)

| 모드 | `Fire`를 짧게 눌렀다 뗄 때 | `Fire`를 계속 누르고 있을 때 |
|---|---|---|
| 단발(Semi) | 정확히 1발 발사 | 추가 발사 없음 — 매번 다시 눌러야 함 |
| 점사(Burst) | `burstCount`만큼 `burstInterval` 간격으로 자동 연속 발사(1회 트리거) | 진행 중인 점사가 끝나기 전까지는 재트리거 무시. 점사가 끝난 뒤에도 계속 누르고 있다고 해서 자동으로 다음 점사가 나가지는 않음 — **결정 사항**: 점사도 매번 다시 눌러야 함(홀드 시 점사가 연쇄로 나가지 않음). 이유: 반동 제어를 플레이어 조작 영역에 남겨 점사 모드의 정체성(단발보다 화력↑, 연사보다 반동 제어 쉬움)을 유지하기 위함. |
| 연사(Auto) | 1발 발사 | `fireRate` 간격으로 탄약/입력이 유지되는 동안 계속 발사 |

- 구현은 Input System의 Interaction보다 **컨트롤러 코드에서 `Fire.IsPressed()` / `Fire.WasPressedThisFrame()`를 직접 읽어 무기의 `currentFireModeIndex`에 따라 분기**하는 방식을 권장한다. 발사 모드가 런타임에 바뀌는 동적 값이라 Input System 바인딩 단계에서 고정하기보다, 얇은 액션 하나(`Fire`)의 로우 데이터를 무기 로직에서 해석하는 편이 유연하다.

## 4. 조준 상태 머신 (우클릭 탭 vs 홀드)

### 4.1 세 가지 상태

| 상태 | 진입 조건 | 특징 |
|---|---|---|
| **Relaxed**(평시) | 기본 상태 | 기본 이동 속도, 기본 반동/탄퍼짐, 하단 힙파이어 자세 |
| **Shouldered**(견착) | `Shoulder`(우클릭 홀드) 트리거되어 있는 동안 | 무기를 어깨에 견착한 자세로 들어 올림. 카메라 줌 없음(FOV 그대로), 힙파이어보다 정확도 소폭 향상, 이동속도 소폭 감소. 홀드를 떼면 즉시 Relaxed로 복귀 |
| **Aiming**(정조준/ADS) | `AimToggle`(우클릭 탭)로 진입, 다시 탭하면 해제 | 카메라 FOV 축소(조준경/아이언사이트 뷰), 정확도 최대, 이동속도 최대 감소, `AimZoomAdjust`로 배율 조절 가능(무기가 가변 배율 조준경일 때) |

### 4.2 상태 전이 규칙

```
Relaxed --(RMB Tap)--> Aiming --(RMB Tap 다시)--> Relaxed
Relaxed --(RMB Hold 시작, 0.2초 경과)--> Shouldered --(RMB Release)--> Relaxed
Aiming  --(RMB Hold)--> (무시, 상태 변화 없음 — 이미 Aiming이 더 상위 자세이므로 Shoulder로 전이하지 않음)
```

- `AimToggle`(Tap)과 `Shoulder`(Hold)는 Input System 상 **같은 RMB 컨트롤에 바인딩된 서로 다른 액션**이며, Tap/Hold 인터랙션 정의상 자연히 상호 배타적으로 트리거된다(release가 빠르면 Tap만, 느리면 Hold만 발동).
- **결정 사항**: `Aiming` 상태에서 다시 RMB를 오래 누르고 있어도 `Shoulder`는 무시한다 — Aiming이 이미 Shoulder보다 상위 호환 자세이므로 별도 처리 불필요, 로직 단순화.
- `Aiming` 중 RMB를 **탭**하면 (진행 중인 hold 타이머와 무관하게) `AimToggle`이 다시 발동해 Relaxed로 복귀한다.
- 아래 상태 전이 시 자동으로 `Aiming`/`Shoulder`가 강제 해제되는 이벤트를 함께 정의해 둔다: `Sprint` 시작, `Reload` 시작, `Melee` 실행, `Crouch`→해제 시 장애물에 걸려 강제 재웅크리기 등. (세부 우선순위는 구현 단계에서 상태 머신 가드로 처리)

### 4.3 정조준 중 배율 조절 (`AimZoomAdjust`)

- `Aiming` 상태이고, 현재 무기가 `hasVariableZoomScope = true`일 때만 마우스 휠 입력을 배율 조절에 사용한다.
- 무기 데이터에 `zoomLevels: float[]`(예: `[2x, 4x, 6x, 8x]`, 이산 단계) 또는 `zoomRange: (min, max)`(연속 가변)를 정의하고, 휠 위로 굴리면 배율 증가, 아래로 굴리면 배율 감소, 최소/최대에서 클램프.
- 고정 배율 스코프(예: 4배율 고정 저격 스코프)나 아이언사이트 무기는 `hasVariableZoomScope = false`로 두어 휠 입력이 무시되도록 한다 — 이 경우 `Aiming` 중에도 휠은 아무 동작을 하지 않음(무기 전환에 쓰이지 않도록 6장 규칙과 함께 명확히 구분).
- 배율 변경 시 FOV 보간(예: 0.1~0.15초)으로 부드럽게 전환해 급격한 시야 변화로 인한 어지러움을 방지.

### 4.4 시점 강제(ViewSwitch 차단)와의 연동

- 저격 소총 등 `forcesFirstPersonOnADS = true`인 무기는 `Aiming` 진입 순간 강제로 1인칭 시점으로 전환되며, 이 동안에는 [시점전환조작설계](./기획문서_시점전환조작설계.md) 3.2절 규칙에 따라 `ViewSwitch`(MMB) 입력이 무시된다. `Aiming`을 해제(RMB 재탭)해야 다시 자유롭게 시점을 바꿀 수 있다.
- 가변 배율 조준경(`hasVariableZoomScope = true`)이라도 `forcesFirstPersonOnADS`가 true라면 시점 강제 규칙이 우선 적용된다 — 두 플래그는 독립적으로 조합 가능(예: "가변 배율 + 강제 1인칭" 저격총, "가변 배율 + 시점 자유" 도트 사이트 등).

## 5. 나머지 전투 액션 개요

### 5.1 재장전 (`Reload`, R)

- 탄창에 여유 탄이 없거나 플레이어가 직접 입력했을 때 재장전 시작. 재장전 중 `Fire` 입력은 무시(또는 무기 타입에 따라 산탄총처럼 셸 단위 재장전이 중간에 캔슬 가능하도록 설계 — 세부는 무기별 후속 설계에서 결정).
- 재장전 중 `AimToggle`/`Shoulder` 상태 진입을 허용할지는 무기별로 다를 수 있음(예: 재장전 중에도 대충 조준 가능한 무기 vs 완전히 무방비인 무기) — 기본안은 **재장전 중 Aiming 진입 금지, 진행 중이던 Aiming은 유지**.

### 5.2 무기 전환 (`WeaponSlot1~4`, `WeaponCycle`)

- 번호키는 항상 즉시 해당 슬롯으로 전환(빈 슬롯이면 무시).
- 마우스 휠은 6장의 컨텍스트 분리 규칙에 따라 비조준 상태에서만 슬롯 순환에 사용.
- `Aiming`/`Shoulder` 상태에서 무기 전환 입력이 들어오면 자동으로 Relaxed로 전이 후 무기 교체 애니메이션 재생.

### 5.3 근접 공격 (`Melee`, V)

- 현재 장비한 무기와 무관하게 항상 사용 가능한 즉발 근접 공격(개머리판/칼 등). `Aiming` 중 사용 시 자동으로 Relaxed 전이.

### 5.4 투척물 (`ThrowLethal`, G)

- 기본안: Press 즉시 투척. **권장 확장안**(6장)으로 Hold 시 쿡오프(뇌관 제거 후 지연시간 카운트) 후 Release 시 투척하는 방식도 고려.

## 6. 추가 권장 사항

### 6.1 마우스 휠 컨텍스트 분리 (`AimZoomAdjust` vs `WeaponCycle`)

같은 마우스 휠을 두 가지 용도로 겹쳐 쓰므로 아래 규칙을 명확히 코드화할 것을 권장한다.

| 조건 | 휠의 의미 |
|---|---|
| `Aiming` 상태 + 무기가 가변 배율 조준경 보유 | 조준경 배율 조절 (`AimZoomAdjust`) |
| `Aiming` 상태이지만 무기가 고정 배율/아이언사이트 | 휠 입력 무시 (아무 동작 안 함) |
| `Relaxed` / `Shouldered` 상태 (비조준) | 무기 슬롯 순환 (`WeaponCycle`) |

두 액션을 Input Actions 에셋에는 둘 다 등록해두되, 실제로 "누가 값을 소비할지"는 위 표에 따라 컨트롤러가 매 프레임 결정하는 방식을 권장한다(Input System 바인딩 단계에서 억지로 분리하려 하면 상태 전이 타이밍에 따라 씹히는 입력이 생길 수 있음).

### 6.2 Tap/Hold 인터랙션 파라미터

- `AimToggle`(Tap)과 `Shoulder`(Hold)의 경계값(0.2초)은 반드시 동일하게 맞춰야 한다(Input System에서 Tap의 `maxTapDuration`과 Hold의 `duration`을 같은 값으로 설정). 값이 어긋나면 "탭도 아니고 홀드도 아닌" 애매한 구간(둘 다 발동 안 함)이 생긴다.
- 체감 테스트 후 0.15~0.25초 사이에서 조정 권장. 너무 짧으면 일반 클릭도 홀드로 오인되고, 너무 길면 빠른 ADS 토글이 굼떠 보인다.

### 6.3 발사 모드 전환 UX

- `FireModeSwitch`(B) 입력 시 HUD에 현재 모드 아이콘/텍스트를 짧게 표시(단발/점사/연사 피드백), 조작 사운드(딸깍 소리 등)도 함께 주는 것을 권장 — 시야 정보 없이도 모드 전환을 인지할 수 있게.
- 무기별로 지원 모드가 다르므로, 무기 전환 시 자동으로 그 무기의 마지막 사용 모드(또는 기본 모드)로 복원되도록 상태를 무기별로 개별 저장할 것을 권장.

### 6.4 Aiming 중 이동/회전 패널티

- `Aiming` 상태의 이동속도 감소율, 몸체 회전 속도 감소, 흔들림(sway) 감소 정도는 무기 종류(권총/소총/저격총)별로 차등 적용할 것을 권장 — 저격총일수록 Aiming 시 이동 패널티를 더 크게 주어 "정지 후 사격" 플레이를 유도.
- `Shouldered` 상태는 Aiming보다 패널티를 가볍게 주어, "빠르게 반응은 하되 정밀도는 낮은" 중간 단계로서 실질적인 선택지가 되도록 밸런싱할 것.

### 6.5 쿡오프(투척물 홀드) 및 근접 처형 등 확장

- `ThrowLethal`을 Hold 인터랙션으로 확장해 쿡오프(뇌관 제거 후 카운트다운) 기능을 넣을 경우, `Shoulder`와 동일하게 Hold 인터랙션을 쓰되 지속시간 게이지를 HUD에 노출할 것을 권장.
- 근접 무기 강화(백어택 처형 등)나 서브 파이어(예: 유탄발사기 연동, 수류탄 런처 등)는 이번 설계 범위 밖이며, 필요 시 `Player` 맵에 `SecondaryFire` 등의 액션을 추가로 정의하는 방향을 권장.

### 6.6 게임패드 대응 (후속)

- `Fire` → Right Trigger, `AimToggle`/`Shoulder` → Left Trigger(트리거의 아날로그 값으로 탭/홀드 대신 "half-press = Shoulder, full-press = Aiming" 같은 아날로그 매핑을 검토), `FireModeSwitch` → D-Pad, `AimZoomAdjust`/`WeaponCycle` → D-Pad Up/Down 등으로 별도 바인딩 세트를 구성할 것을 권장(키보드 설계를 그대로 옮기지 말고 아날로그 트리거의 특성을 활용).

## 7. 결정 사항 요약

- 무기/전투 액션은 별도 Action Map이 아니라 **`Player` 맵에 통합**(캐릭터 조작과 항상 같은 시점에 켜지고 꺼지므로).
- `Fire`(좌클릭)는 단일 버튼 액션으로 두고, **발사 모드 해석은 코드(무기 로직)** 에서 처리 — 단발은 매번 재입력 필요, 점사는 트리거당 고정 버스트(홀드해도 연쇄 발사 안 됨), 연사는 홀드 중 지속 발사.
- 우클릭은 **Tap(`AimToggle`, ≤0.2초) / Hold(`Shoulder`, ≥0.2초)** 로 분리. 탭하면 정조준(ADS) 토글, 홀드하는 동안만 견착 자세 유지(떼면 해제).
- 상태 머신: **Relaxed → Shouldered(홀드 중) / Relaxed ↔ Aiming(탭 토글)**. Aiming 중에는 홀드를 추가로 받아도 Shoulder로 전이하지 않음.
- 정조준 중 마우스 휠은 **가변 배율 조준경 무기에 한해** 배율 조절(`AimZoomAdjust`)에 사용. 비조준 상태에서는 같은 휠이 무기 슬롯 순환(`WeaponCycle`)에 사용됨(6.1 컨텍스트 분리 규칙).
- `FireModeSwitch`(B)는 무기별 지원 모드 목록 안에서만 순환, 1개 모드만 지원하는 무기는 전환 불가.
- 재장전(R), 근접(V), 투척(G), 무기 슬롯(1~4)을 기본 세트로 확정. `V`/`G`는 기존 캐릭터 조작 키(WASD/Space/C/Shift/Q/E/F/Alt)와 충돌 없음.
- 권장 사항: Tap/Hold 임계값 동일화, 발사 모드 전환 HUD 피드백, 무기별 Aiming 이동 패널티 차등화, 쿡오프형 투척 확장, 게임패드 별도 바인딩 세트.
