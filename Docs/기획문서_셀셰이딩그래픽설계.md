# 셀셰이딩 & 빗금(해칭) 그림자 그래픽 파이프라인 설계

> 이 프로젝트(Unity 6, URP)의 렌더링 스타일을 **셀셰이딩(Cel Shading)** 으로 정의하고, 그림자를 단색 어둡게 칠하는 대신 **빗금(해칭) 패턴**으로 표현하는 커스텀 셰이딩 파이프라인을 설계한다. 그림자가 강할수록(더 어두울수록) 빗금의 밀도가 높아지도록 한다.
> 실제 셰이더 코드/텍스처 제작은 범위 밖이며, 본 문서는 **셰이딩 모델과 데이터 구조, 결정 사항**을 정의한다.
> 작성일: 2026-09-17

---

## 1. 설계 원칙

1. **톤(명암)은 이산 밴드로 양자화**한다 — 일반적인 셀셰이딩처럼 조명값을 연속적인 그라데이션이 아니라 몇 단계의 뚜렷한 단(band)으로 끊어 표현한다.
2. **그림자 밴드는 단색이 아니라 빗금 오버레이로 표현**한다. 어두운 밴드일수록 빗금 레이어가 더 많이 겹쳐 밀도가 높아지고, 가장 어두운 영역은 크로스해칭(교차 빗금)에 가까워진다 — 손으로 그린 잉크 해칭(만화/판화 음영 기법)을 시뮬레이션.
3. **아트 리소스 제작 비용을 최소화**한다. 해칭 텍스처를 화가가 여러 장 그려야 하는 방식(Tonal Art Map류) 대신, **셰이더 내에서 절차적으로 선을 생성**해 머티리얼 파라미터만으로 조절 가능하게 한다 — 이 프로젝트가 소규모 샌드박스 프로젝트인 점을 고려한 결정.
4. **캐릭터 실루엣 가독성(슈팅 게임 핵심 요구사항)을 해치지 않는다** — 해칭이 아무리 화려해도 "적이 어디 있는지" 즉시 읽혀야 하므로, 밝은 영역(Lit 밴드)은 항상 빗금 없이 깨끗하게 유지한다.

---

## 2. 렌더링 파이프라인 개요

- URP의 기본 Lit 셰이더를 쓰지 않고, **커스텀 Shader Graph(또는 동등한 HLSL 셰이더)** 를 제작해 모든 캐릭터/오브젝트에 적용한다.
- 조명 입력은 URP의 Main Light 구조체에서 가져온다: `GetMainLight()`로 방향/색상/그림자 감쇠(shadow attenuation)를 얻고, 필요 시 Additional Light도 같은 톤 양자화 로직을 거치게 한다.
- 재사용성을 위해 톤 계산 + 해칭 오버레이 로직을 **Shader Graph Sub Graph(`ToonHatchLighting`)** 로 만들어, 캐릭터/무기/환경 오브젝트 셰이더가 공통으로 가져다 쓰도록 한다.

## 3. 톤(명암) 밴드 설계

| 밴드 | 조건 | 표현 방식 |
|---|---|---|
| Lit(밝음) | `toneValue < band1Threshold` | 베이스 컬러 그대로, 해칭 없음 |
| Shadow(그림자) | `toneValue >= band1Threshold` | 베이스 컬러 위에 해칭 오버레이 적용(밀도는 `toneValue`에 비례, 5장) |
| Rim(윤곽, 선택) | 시야각 기준 페넬 항 | 실루엣 강조용 얇은 밝은/어두운 테두리(8장 권장 사항) |

### 3.1 `toneValue` 계산 (0 = 완전히 밝음, 1 = 완전히 어두움)

```
toneValue = saturate(
    (1 - NdotL) * lightWeight            // 정반대 방향일수록 어두움
    + (1 - mainLightShadowAttenuation) * shadowWeight  // 그림자맵에 가려졌으면 추가로 어두움
    + (1 - ambientOcclusion) * aoWeight   // 크레바스/틈새 AO(선택)
)
```

- **결정 사항**: `NdotL`(램버트 항), 실시간 그림자맵 감쇠, AO(선택) 세 요소를 가중합해 `toneValue`를 만든다 — 단순히 `NdotL`만 쓰면 그림자맵으로 인한 그늘(다른 오브젝트가 드리운 그림자)이 해칭으로 표현되지 않아 "그림자가 강할수록 빗금이 밀도 높게"라는 요구를 절반만 만족하게 되므로, 반드시 그림자 감쇠 항을 포함한다.
- 기본 가중치 예시: `lightWeight = 0.6, shadowWeight = 0.4, aoWeight = 0.2`(합이 1을 넘을 수 있으므로 최종 `saturate`로 클램프) — 밸런싱은 아트 디렉션 단계에서 조정.

## 4. 빗금(해칭) 오버레이 설계

### 4.1 절차적 해칭 vs 아트 텍스처 — 결정

| 방식 | 장점 | 단점 |
|---|---|---|
| 아트 텍스처(Tonal Art Map류, 여러 밀도의 손그림 해칭 텍스처를 톤 레벨별로 제작) | 손맛이 살아 있는 고품질 결과 | 텍스처 제작 비용 큼, 톤 레벨/LOD별로 다수 텍스처 필요 |
| **절차적 셰이더 해칭(채택)** | 텍스처 제작 불필요, 파라미터(각도/굵기/간격)로 즉시 튜닝, 텍스처 메모리 0 | 손그림 특유의 불규칙함은 부족(8장에서 노이즈로 보완) |

- **결정 사항**: 절차적 방식을 채택한다(1.3절 원칙과 동일한 이유).

### 4.2 해칭 레이어 구성

- 해칭은 **N개(기본 4개)의 선 레이어**로 구성되며, `toneValue`가 커질수록(더 어두워질수록) 레이어가 하나씩 추가로 활성화되어 겹쳐진다 — 겹칠수록 크로스해칭이 되어 밀도가 자연스럽게 올라간다.

| 레이어 | 활성 임계값(toneValue) | 선 각도 | 의도 |
|---|---|---|---|
| L1 | 0.25 | 45° | 첫 음영 — 가벼운 사선 |
| L2 | 0.5 | -45° | L1과 교차 — 본격적인 크로스해치 시작 |
| L3 | 0.75 | 0°(수평) | 추가 교차로 더 어둡게 |
| L4 | 0.9 | 90°(수직) | 최고 밀도 — 사실상 거의 채워진 어둠 |

- 레이어 i의 마스크: `linePattern = triangleWave(dot(hatchCoord, lineDir_i) * frequency_i)`, `lineMask_i = smoothstep(lineThickness - aa, lineThickness + aa, linePattern)` (`aa`는 4.4절의 안티에일리어싱 폭).
- 최종 해칭 커버리지: `hatchCoverage = saturate(sum(lineMask_i for i where toneValue >= threshold_i))` — 레이어가 많이 겹칠수록 자연스럽게 1(완전히 덮임)에 가까워진다.
- **결정 사항**: 레이어별로 각도를 다르게 주어(45°→-45°→0°→90°) 실제 손 해칭처럼 "방향을 바꿔가며 겹쳐 어둡게 만드는" 느낌을 낸다 — 모든 레이어를 같은 각도로 쌓으면 그냥 선이 굵어지는 것처럼만 보여 해칭 특유의 질감이 안 산다.

### 4.3 좌표계(hatchCoord) — 오브젝트별 다른 전략 채택

| 대상 | 좌표계 | 이유 |
|---|---|---|
| 히어로 캐릭터(플레이어/주요 NPC) | **UV2(아티스트가 별도로 펼친 해칭 전용 UV)** | 선의 흐름을 몸의 형태(근육 결/옷 주름 방향)에 맞춰 의도적으로 배치 가능 — 손으로 그린 것 같은 품질 |
| 환경/소품/몹 다수 스폰 오브젝트 | **월드 공간 트라이플래너(Triplanar) 좌표** | UV 제작 비용 없이 자동 적용, 다량의 오브젝트에 일괄 적용 가능 |

- **결정 사항**: 전부 트라이플래너로 통일하면 제작은 쉽지만 캐릭터 형태에 선이 "붙어있지 않고 떠 있는" 느낌이 나서 품질이 떨어지므로, 주인공/핵심 NPC에 한해 UV2 제작 비용을 감수한다. 이 판단 기준(무엇이 "히어로"인가)은 아트 디렉션 단계에서 목록화.

### 4.4 밴드/레이어 전환 안티에일리어싱

- 톤 밴드 경계와 각 해칭 레이어의 활성 임계값 모두에서, 화면 공간 미분값(`fwidth`)을 이용해 **경계 폭 약 2~4픽셀**의 부드러운 전환을 준다 — 완전히 하드 엣지로 자르면 카메라/오브젝트가 조금만 움직여도 경계가 픽셀 단위로 깜빡여(시밍) 지저분해 보이기 때문. 셀셰이딩 특유의 "딱 끊어지는" 느낌은 유지하되, 그 끊어지는 선 자체는 살짝만 부드럽게 처리하는 절충.

### 4.5 잉크 색상

- 해칭 선의 색은 순수 검정이 아니라 **베이스 컬러를 어둡게 만든 색**(`hatchColor = baseColor * 0.15`)을 기본값으로 한다 — 재질 고유의 색감이 그림자에서도 은은히 비치게 하기 위함. 머티리얼별로 오버라이드 가능하게 파라미터로 노출.
- 해칭 오버레이는 베이스 컬러에 `Lerp(baseColor, hatchColor, hatchCoverage)` 형태로 블렌딩한다(곱연산이 아니라 보간을 써서, 완전히 덮인 영역도 새까맣게 죽지 않고 `hatchColor`로 은은하게 유지).

## 5. 구현 메모 (Shader Graph / HLSL 의사코드)

```hlsl
float3 ToonHatchLighting(float3 baseColor, float3 worldPos, float3 worldNormal, float2 hatchUV, bool useTriplanar)
{
    Light mainLight = GetMainLight(TransformWorldToShadowCoord(worldPos));
    float NdotL = saturate(dot(worldNormal, mainLight.direction));
    float shadowAtten = mainLight.shadowAttenuation;

    float toneValue = saturate((1 - NdotL) * 0.6 + (1 - shadowAtten) * 0.4);

    float2 hatchCoord = useTriplanar ? TriplanarCoord(worldPos, worldNormal) : hatchUV;

    float hatchCoverage = 0;
    UNITY_UNROLL
    for (int i = 0; i < 4; i++)
    {
        if (toneValue >= _HatchThreshold[i])
            hatchCoverage += HatchLineMask(hatchCoord, _HatchAngle[i], _HatchFrequency[i], _HatchThickness);
    }
    hatchCoverage = saturate(hatchCoverage);

    float3 hatchColor = baseColor * 0.15;
    return lerp(baseColor, hatchColor, hatchCoverage);
}
```

- `_HatchThreshold[4] = {0.25, 0.5, 0.75, 0.9}`, `_HatchAngle[4] = {45, -45, 0, 90}` 를 머티리얼 프로퍼티(또는 Sub Graph 기본값)로 노출해 아트 디렉션 단계에서 손쉽게 튜닝하게 한다.

## 6. 결정 사항 요약

- 조명은 **이산 톤 밴드(Lit/Shadow)** 로 양자화하고, 그림자 밴드는 단색이 아니라 **해칭 오버레이**로 표현.
- `toneValue`는 **NdotL + 그림자맵 감쇠(+선택적 AO)** 가중합으로 계산 — 다른 오브젝트가 드리운 그림자도 해칭 밀도에 반영되도록 함.
- 해칭은 **절차적 셰이더 방식**(아트 텍스처 대신)으로 채택, 텍스처 제작 비용 0.
- 해칭은 **4개 레이어**, 톤이 어두워질수록 레이어가 하나씩 추가로 활성화되며 **각도를 다르게 교차**시켜 크로스해치 질감을 냄.
- 좌표계는 **히어로 캐릭터=UV2 수작업, 환경/다수 오브젝트=트라이플래너**로 이원화.
- 밴드/레이어 경계는 `fwidth` 기반 2~4픽셀 소프트 전환으로 시밍 방지.
- 잉크 색은 순수 검정이 아니라 **베이스 컬러를 어둡게 한 색**을 기본값으로 사용.

## 7. 추가 권장 사항

- **아웃라인(윤곽선)**: Inverted Hull 또는 노멀 기반 엣지 디텍션으로 캐릭터 외곽에 얇은 잉크 라인을 추가하면 셀셰이딩 + 해칭 스타일과 시각적으로 잘 어울림 — 실루엣 가독성(1.4절)도 더 강화됨.
- **툰 스페큘러**: 하이라이트도 그라데이션이 아니라 경계가 뚜렷한 단일 블롭으로 처리해 전체적인 톤 일관성 유지.
- **거리 기반 해칭 밀도 감쇠**: 카메라에서 먼 오브젝트는 `_HatchFrequency`를 낮춰(선 간격을 넓혀) 무아레(모아레) 패턴과 과도한 셰이더 비용을 방지할 것을 권장 — LOD와 연동.
- **손그림 불규칙성 추가(선택)**: 완전히 규칙적인 절차적 선이 너무 기계적으로 보이면, 저주파 노이즈로 선의 두께/위치를 미세하게 흔들어(jitter) 손맛을 더하는 방향을 후속 검토.
- **성능 프로파일링**: 트라이플래너 3방향 샘플링 + 4레이어 루프는 픽셀 셰이더 비용이 URP 기본 Lit 대비 높으므로, 모바일/저사양 타겟이 생기면 레이어 수를 2개로 줄이는 품질 옵션(Quality Setting)을 권장.

- 아웃라인 셰이더 세부 설계.
- 모바일/저사양 대응 품질 옵션(Quality Tier) 설계.
